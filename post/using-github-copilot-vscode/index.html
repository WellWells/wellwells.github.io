使用 GitHub Copilot 的代理模式以提升撰寫程式的效率與開發體驗

VS Code 代理模式結合 GitHub Copilot 與 MCP 的使用紀錄：三種操作模式的差別、模型與方案計價比較、C 專案初始化示範，以及接上 PostgreSQL MCP 用自然語言查資料庫。

前言

VS Code 於 2025 年 4 月 7 日正式在 Visual Studio Code 穩定版全面推出代理模式（agent mode），並支援模型上下文協定（model context protocol，MCP）。

看完相關說明後我馬上開始用，隔天也在工作上推廣、討論代理模式的應用。代理模式改變了我原本的開發流程，專案推進的速度差很多，是值得早點上手的工具。

在新專案開發階段，開發者經常需處理基礎環境建置、工具安裝與大量文件閱讀等任務。這時可以直接在 VS Code 代理模式下指派代理執行相關指令，很快就能拿到精確的指引，學習曲線與開發時間都縮短不少。

代理模式在本月初推送到 VS Code 穩定版，到現在大約兩週，我已經把它整合進日常開發流程。這篇會講我結合 GitHub Copilot 的實際使用經驗與觀察。

什麼是 GitHub Copilot

GitHub Copilot 是一款由 GitHub 與 OpenAI 共同開發的 AI 程式輔助工具，主要功能是協助開發人員更快速、更輕鬆地撰寫程式碼，讓開發者能將更多精力投入在解決問題與團隊合作上。

主要功能

即時程式碼建議：當開發者在 Visual Studio Code、JetBrains IDE、Neovim 等整合開發環境（integrated development environment，IDE）撰寫程式時，Copilot 能根據目前編輯的內容和上下文，預測並建議下一行甚至整個函式的程式碼，開發速度快很多。

自然語言互動：開發人員可使用自然語言（如中文、英文或慣用語言）與 Copilot Chat 對話，請求解釋複雜程式碼、產生單元測試、協助除錯、重構現有程式，甚至將程式碼轉換成其他程式語言。

多平台整合：Copilot 不僅能在各種 IDE 中使用，還能在 GitHub Mobile 應用、命令列介面、Windows Terminal 以及 GitHub 網站上提供協助。

知識庫與文件產生：企業方案中，團隊可建立專屬的技術知識庫，使 Copilot 更貼近專案需求，同時還能協助自動產出高品質的 pull request 說明文件，節省大量溝通成本。

操作模式

GitHub Copilot 有三種操作模式，權限與適用場景各不相同，以下依系統權限與操作範圍由小到大排列。

詢問模式
（Ask mode）		編輯模式
（Edit mode）		代理模式
（Agent mode）
權限層級唯讀修改程式碼檔案完整系統操作權限與終端機互動
回傳內容形式純文字回答文字回答 + 自動修改/新增程式碼自動化執行開發任務，含套件安裝與結構修改
適用情境程式語法、概念解釋、API 使用說明等程式碼重構、功能實作、樣式調整、錯誤修正開發環境建置、專案初始化、自動化開發任務
實例操作僅分析與建議程式碼直接修改操作專案結構、安裝套件、執行終端命令等
實作能力不會實際變更程式碼可修改與最佳化程式碼可自動化開發與整合

在實際開發過程中，處理簡單查詢和程式碼理解時，我會採用詢問模式；而需要執行更複雜的開發任務，如環境設定、套件安裝或專案結構調整時，則直接使用功能最完整的代理模式。

方案費用差異

免費版本有一些限制，限制範圍以綁定的 GitHub 帳號為主。用量更大的話就得升級付費方案，才有穩定的服務品質與進階模型的存取權限。

免費版本限制條件如下：

  1. 每月最多 2,000 次程式碼自動完成（code completions）。
  2. 每月最多 50 次 Copilot Chat 對話訊息（涵蓋 IDE、終端機與命令列等介面）。
  3. 所有限制均於每月自動重置。

教育與開源社群優惠方案

學生、教育工作者與活躍的開源專案維護者均可免費申請 GitHub Copilot Pro。

學生申請資格相對簡單，只需在個人帳號中輸入學校發放的教育信箱進行認證，並上傳相關身分證明文件（如學生證、在學證明或成績單）。通常審核時間約為 3 至 5 天。若驗證未通過，系統會告知缺少哪些資料，補齊後即可再次提交申請。

學生申請流程：

  1. 在 GitHub 個人帳號中綁定學校發放的教育信箱。
  2. 上傳有效身分證明文件（學生證、在學證明或成績單）。
  3. 等待審核約 3-5 個工作天。
  4. 若申請未通過，系統會指明所需補充資料，可再次提交。

在 VS Code 中使用 GitHub Copilot

  1. 開啟 Visual Studio Code。

  2. 安裝 GitHub Copilot 擴充功能

    • 點選左側活動欄的擴充功能圖示（Extensions）。
    • 在搜尋框輸入 Copilot。
    • 找到官方的 GitHub Copilot 與 GitHub Copilot Chat 擴充功能並點選安裝。

  3. 登入 GitHub 帳號

    • 安裝完成後，VS Code 會自動彈出通知，提示登入 GitHub。也可以點左下角帳戶圖示，手動登入 Copilot。
    • 按照指示完成授權流程，允許 Copilot 存取個人帳號。

  4. 登入後，VS Code 右下角會顯示 GitHub Copilot 狀態與用量資訊。

  5. 點選 VS Code 上方的 GitHub Copilot 按鈕，或使用快速鍵 Ctrl + Alt + I 開啟 Copilot 視窗。

  6. 可以將資料夾/檔案拖曳至 Copilot Chat 視窗，讓 Copilot 取得專案內容來分析。也可以用 # 互動變數讓對話更有效率、更精準。

    例如常用的 #codebase 可讓 LLM 讀取並分析整個專案目錄；#fetch 則可抓取特定網頁內容後分析並回應。

啟用 GitHub Copilot 代理模式

  1. 開啟 Visual Studio Code 設定

    使用快速鍵 Ctrl + 逗號，或點選左下角齒輪圖示以開啟設定視窗。

  2. 搜尋並啟用代理模式功能

    在設定搜尋框中輸入 agent，並啟用 Chat > Agent 選項。啟用後，即可於 GitHub Copilot Chat 中使用代理模式功能。

  3. 疑難排解

    我另一台電腦更新 VS Code 至最新版後找不到 Chat > Agent 選項，照以下步驟重置使用者設定後就出現了：

    • 關閉 VS Code。
    • 刪除 %appdata%\Code 目錄。
    • 重新啟動 VS Code。

    以下指令可用於快速刪除該目錄（注意：此操作將清除所有使用者設定與快取資料）：

1

cmd /c rmdir /s /q "%appdata%\Code"

使用 PostgreSQL MCP 伺服器

PostgreSQL MCP 伺服器允許 AI 工具（如 Claude Desktop 或 Visual Studio Code）直接與 PostgreSQL 資料庫互動，用自然語言查詢來分析和操作資料。

  1. 首先，開啟專案目錄。
  2. F1 呼叫功能視窗，輸入 mcp，選擇MCP: 新增伺服器
  3. 選擇 NPM 套件，並輸入 @modelcontextprotocol/server-postgres
  4. 照著流程安裝，伺服器識別碼可以預設也可以是專案名稱，最後儲存在專案目錄下。
  5. 此時專案目錄會多一個 mcp.json，將預設的連線 URL postgresql://localhost/mydb 改為對應的伺服器網址與資料庫。
  6. 修改完畢後，開始這個 MCP 伺服器。
  7. 在代理模式下，選擇該 MCP 伺服器。

  1. 後續詢問伺服器相關的內容，代理模式下可以執行 SQL 相關指令，並回饋資料庫狀態。

結論

GitHub Copilot 代理模式讓我幾個長期卡住的專案有了進展。以前遇到模糊、不熟悉或難以定義的問題，往往要花大量時間搜尋資料、反覆試錯，現在用自然語言把需求描述清楚，就能拿到具體、可執行的做法。

以我目前的開發經驗來說，前端應用的快速實作、技術問題的診斷排除，Copilot 都做得很穩。只要目標與規格定清楚，代理模式就能自動完成大部分開發任務。

PostgreSQL MCP 伺服器與開發環境的整合，把自然語言和資料庫操作接了起來。對不熟悉複雜 SQL 語法的人特別有用，用日常語言就能完成資料庫查詢、結構檢視及基本的增刪改查。

把代理模式接上 MCP 之後，最有感的是查資料、操作資料庫這些事不用再離開編輯器，排查問題的來回時間也跟著減少。所以我會建議直接把它放進日常開發流程。
