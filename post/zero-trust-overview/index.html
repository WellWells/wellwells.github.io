零信任全面解析：理念、現況與未來

零信任的「永不信任，一律驗證」是什麼、傳統 VPN 為什麼會過度授權，並以從外網存取公司 NAS 為例，比較 Tailscale 與 Cloudflare Zero Trust 的做法。

前言

傳統上，企業提供虛擬私人網路（virtual private network，VPN）給員工遠端存取，但這種模式正普遍面臨挑戰。根據 Tailscale 最新的《2025 零信任狀態》白皮書，數據顯示：

  • 高達 90% 的組織在使用現有 VPN 時至少遇到一個問題。
  • 更有 99% 的公司希望重新設計其存取和連接方式。

這些數據清楚表明，傳統的「城堡加護城河」網路安全模型已走入死胡同。過去將網路切割為可信內部與不可信外部的架構，在今日混合辦公、雲端服務與行動裝置普及的環境下，已無法有效阻絕各類威脅。

這篇文章要談的是傳統 VPN 的局限，並用一個常見的實際案例，也就是從外網存取公司內部的網路儲存伺服器（network attached storage，NAS）檔案，來說明零信任架構怎麼解決這些痛點。

傳統 VPN 模式的固有挑戰

傳統 VPN 的設計初衷是將遠端使用者帶回公司內網，使其彷彿置身於辦公室。但這種設計也帶來了三大固有缺陷：

  1. 過度寬鬆的權限：一旦連上 VPN，使用者通常就獲得了對整個內部網路的廣泛存取權，這遠遠超出了其工作所需。
  2. 嚴重的安全風險：白皮書中 40% 的受訪者將「安全風險」列為 VPN 的首要問題。一旦 VPN 憑證外洩，攻擊者就等於拿到了一把能打開公司所有大門的萬能鑰匙，可以在內網中自由漫遊，進行橫向移動（lateral movement），尋找下一個攻擊目標。
  3. 效能瓶頸與使用者體驗不佳：遠端流量必須先經中央閘道再轉送至目標，造成路徑冗長，延遲增加、頻寬受限，整體生產力也跟著受影響。

實際案例：存取企業內部 NAS
以一名員工在家存取內部 NAS 上的企劃檔案為例：

  1. 員工啟動 VPN、輸入憑證並連線成功，電腦即成為內網一部分。
  2. 若駭客竊取該憑證，不僅能直接存取 NAS，還能掃描並攻擊內部其他伺服器與資料庫。
  3. 此即為典型的「橫向移動攻擊風險」。

零信任架構就是要擋掉這類基於網路位置的隱性信任，只授予使用者所需的最小權限。

零信任的核心原則與實現技術

零信任是一種現代化安全模型，其核心理念為「永不信任，一律驗證（Never Trust, Always Verify）」，並摒棄傳統基於網路邊界的隱性信任假設，建立在以下三大原則之上：

  1. 明確驗證：無論使用者或設備位在何處，每次存取請求都要嚴格做身分驗證與授權。
  2. 最小權限存取：僅授予使用者完成工作所需的最小權限，縮小潛在的攻擊面。
  3. 假設威脅存在：預設網路中任一位置（內外部）皆可能遭受威脅，須持續監控並驗證。

技術上，零信任網路存取（zero trust network access，ZTNA）是落實零信任原則的核心技術。其運作模式與傳統 VPN 存在根本上的不同：

  • 傳統 VPN 的存取模型：將通過驗證的使用者存取整個可信的企業內網。這相當於交付使用者一把能打開整棟大樓所有門的萬能鑰匙，使其能接觸到超出其需求的網路資源。
  • ZTNA 的存取模型：為每一個應用程式或資源建立獨立的、受保護的存取通道。它僅在驗證通過後，才動態地為使用者與該特定資源建立連線。這好比每次都只為使用者打開特定一個房間的門，而非整棟大樓。

根據白皮書顯示，68% 的受訪者在離職後仍保有公司部分系統的存取權限，其中 32% 在離職當下即被移除，22% 在數日內、27% 在數週內、13% 在數月後，甚至有 2% 要等數年才被撤銷。

零信任架構的部署實務

以存取內部 NAS 為例，IT 管理人員若要遵循零信任原則，可依據不同技術路徑選擇方案，其中以 Tailscale 和 Cloudflare Zero Trust 為兩種知名做法。

Tailscale

  • 核心機制：採用基於 WireGuard 的點對點加密網路（Tailnet），設備間通訊為端對端加密，中繼伺服器無法窺探流量內容。

  • 使用者端設定：管理員需在各設備安裝 Tailscale 應用程式，並用公司的身分提供者（如 Apple、Google、Github、Microsoft、Okta 等）登入，把設備加入 Tailnet。

  • 流量路徑：在理想情況下，設備間流量會直接以點對點連線傳輸，延遲低、效能好。當 NAT 穿透失敗時，流量會自動改走 Tailscale 的 DERP（designated encrypted relay for packets）中繼伺服器，依舊維持端對端加密。

  • 存取方式：Tailscale 會自動為每台設備分配 100.x.y.z 的虛擬 IP 位址，並可搭配 MagicDNS 功能直接用設備名稱存取，簡化主機解析與連線設定。

  • 授權機制：管理員可用 Tailnet 的存取控制清單（access control list，ACL）機制，基於使用者身分、群組或設備標籤（Tag），在政策檔中以拒絕預設（deny-by-default）原則定義最小權限存取規則。

Cloudflare Zero Trust

  • 核心機制：CFZT 將傳統網路邊界轉移至 Cloudflare 的 Anycast 全球網路中，並以零信任原則在雲端執行身分與安全策略驗證後，再連線至內部資源。

  • 使用者端設定：可選擇 WARP 用戶端模式（安裝 Cloudflare WARP，將設備流量導向 Cloudflare 雲端，以執行 Gateway 與 Access 策略驗證）或無用戶端瀏覽器模式（Clientless Browser Access，不用安裝任何程式，直接在瀏覽器中存取 Web 應用）。

  • 流量路徑：所有請求均先導向最近的 Cloudflare PoP（Point of Presence）節點，Cloudflare 會在雲端完成身分驗證、裝置檢查與安全掃描，通過後再由部署於內網的 Connector 把流量安全轉送到目標資源。

  • 存取方式：使用者以 Cloudflare 代理的私有或公開 FQDN（完整網域名稱）存取資源；DNS 解析與連線控制皆由 Cloudflare 管理，僅在通過身分與安全策略授權後才可到達目標伺服器。

  • 授權機制：在 Cloudflare 儀表板中，可用 Cloudflare Access 定義多重條件授權，包括使用者身分、地理位置、裝置狀態（如是否安裝 WARP、磁碟加密、防毒版本）及網路屬性等，落實最小權限原則。

結論

傳統 VPN 的局限性正加速零信任架構的普及，這已經是一場正在進行的安全典範轉移。前面談了傳統存取模式的風險，也以 Tailscale 和 Cloudflare Zero Trust 為例，看「永不信任，一律驗證」怎麼用這些現成的工具做到。對個人使用者來說免費方案就很夠用，對企業來說可以按需付費、快速部署，零信任網路現在就能採用。

這場變革的核心，是把信任的基礎從模糊的網路邊界，移到清楚的數位身分上。不管是點對點的 Mesh VPN 還是雲端代理的 ZTNA，共同目標都是最小權限存取（least privilege access），每一次連線都要經過嚴格驗證，讓橫向移動沒有路可走。

對於想立即開始，卻對 VPN、內網穿透、反向代理、NAT 打洞等技術術語感到陌生的個人使用者，其實起步很簡單。可以參考我先前的文章《使用 Tailscale 輕鬆建立安全且私密的隧道》之如何安裝 Tailscale 章節，只需在兩台設備上用同一個帳號登入，就可以安全地建立點對點連線。就這麼簡單，恭喜你已經成功建立你自己的零信任網路了。

這背後就是零信任的核心：一切基於身分驗證，只要登出，連線隨即中斷。把這個模式延伸到企業，員工用 Okta、Microsoft Entra ID 或 Google Workspace 這些身分提供者驗證，IT 管理員只要在身分提供者裡停用員工帳號，他在所有應用的存取權限就會即時自動撤銷，不用手動去各個系統刪權限，安全性與管理效率都好很多。更複雜的策略驗證也做得到，可以再往動態的零信任架構走。
