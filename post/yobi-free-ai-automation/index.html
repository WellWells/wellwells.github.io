為什麼自己搭 AI Agent 這麼難

假設你想弄一個小幫手，每天定時幫你把固定幾個網站的新內容抓回來、整理成一份摘要。就這種固定來源、定時統整的小事，照現在主流自己搭 AI Agent 的做法，大概會是這樣：先準備一台電腦，裝上像 OpenClaw 這類工具，再跟著一長串教學做一連串設定。光是把環境弄起來加上密密麻麻的內容，就先卡掉不少人。

接下來還要選模型，而且不管走哪一條，都各有各的門檻。

選本地模型：模型權重得整包塞進記憶體裡跑（一般 PC 主要吃顯卡的 VRAM，而 Apple Silicon 是統一記憶體）。入門大概 12～16GB 才跑得動 7B～14B 這種小模型；但這個等級的小模型短板很明顯，回答品質偏弱、容易出錯、複雜一點的指令也常常跟不上。真的要堪用，普遍得上到 30B 等級的模型，光是 Q4 量化後的權重就要 22～24GB，換算下來記憶體大概要 24～32GB 起跳，等於要先換一台不便宜的機器。

選雲端模型：一開始就得綁信用卡、開始按 Token 計算用量。

於是就變成什麼都還沒開始做，光是準備這一步，就要先花錢買硬體或是先綁卡被收費。這一關，我覺得就讓很多人怯步了。

再加上這類工具的教學大多是英文，網路上看起來琳瑯滿目，但真的能長時間在系統穩定運作執行的少之又少。常常照著做到一半，才發現版本對不上、或服務早就收掉了。

更現實的是，整個 AI 生態的版本迭代實在太快，套件三天兩頭就更新，光是跟著升級就夠累。而迭代快的另一面，是安全風險也跟著來，這類專案連同它一長串的相依套件，三不五時就爆出 CVE 漏洞。自己架一套 Agent，等於要一邊追新功能、一邊補安全洞，長期維護的成本遠比一開始想的還高。

其實大部分的事都能變成固定流程

但回頭想想，我們每天在電腦上做的事，很多其實都是固定的步驟，可以像 iOS 的捷徑一樣事先排好。

把整個流程裡機械式的部分（抓資料、搬檔案、傳訊息）先用步驟固定下來，只把真正需要理解、判斷的那一小段交給 LLM 去整理或分析。這樣做有兩個好處：一是整體跑起來更快，二是 Token 用量會少很多，因為你不是每件事都丟給 AI 從頭想，而是只在關鍵的地方才用到它。

而且這樣做還多了一個更重要的特性：可預期。如果讓 AI 從頭到尾自己決定每一步，結果常常不太穩定，今天這樣跑、明天那樣跑；但把 LLM 放進一條你事先排好的固定流程裡，它只負責中間那段你交辦的判斷，前後的輸入輸出都在你的掌握之中，每次跑出來的結果自然就一致。

Yobi 就是往這個方向做的，目標是讓你用最少的力氣，快速搭出一個屬於自己的簡易 AI Agent，把日常那些瑣碎、固定的任務交給它。

Yobi 是什麼

Yobi 是一款本機優先、開源（MIT）的 AI 自動化桌面應用，支援 Windows 與 macOS。

它的運作方式很單純，內建一個瀏覽器視窗，幫你把 ChatGPT、Gemini、Perplexity、Duck.ai 的網頁開起來，把你的提示詞打進頁面、再把回應讀回來，跟你自己開網頁用是同一回事。它不呼叫各家的官方 API，也不在你電腦上跑任何 AI 模型。需要登入的，沿用你瀏覽器裡已經登入的工作階段就好；像 Gemini、Duck.ai 這些，預設不登入也能直接用。（如果你手上本來就有 API 金鑰，設定裡也有 BYOK 模式可以接上，但那是選配，預設還是走網頁。）

正因為走的是各家自己的網頁、而不是付費的 API，你才不用辦 API 金鑰、也不用綁卡付費，連架本地模型的那道硬體門檻也一起省掉了。

打開 Yobi，第一眼看到的就是一個跟大多數 AI 服務一樣的聊天視窗，挑一家 AI、直接打字就能聊。

自動化操作這些網頁介面，本身是違反各家服務條款的。Yobi 不會去繞過任何技術防護，不解 CAPTCHA、不規避速率限制，也不做 IP 輪替。一般個人的輕量使用，最常遇到的頂多是偶爾跳一次確認你是真人的驗證，自己手動點掉就好；真正容易被擋的，是大量、濫用式的自動化。請自己拿捏著用，別拿它做任何違法的事。

它走的是個人電腦這條路，平常工作用的那台，或是家裡 24 小時不關機的主機，都很適合讓它常駐著跑；而且全程都是 GUI 操作，不用碰任何指令列。

下載與安裝 Yobi

Windows 直接從 Microsoft Store 安裝最省事，裝完會自動更新，也不會跳未簽章的警告。想手動裝的話，Releases 頁面也有 x64 安裝檔；因為還沒買簽章憑證，第一次執行 Windows 會跳保護視窗，點「其他資訊 → 仍要執行」就能繼續。

macOS 到 Releases 抓 .dmg，M1／M2／M3／M4 晶片抓檔名有 arm64 的，Intel 抓 x64 的。不確定自己的 Mac 是哪一種？點螢幕左上角的蘋果選單 →「關於這台 Mac」，看晶片／處理器那一欄。.dmg 點開後，把 Yobi 拖進「應用程式」資料夾就裝好了。

macOS 第一次打開被擋住是正常的。 這個 App 目前還沒做 Apple 的付費簽章，第一次開，系統會跳出「無法打開，因為來自未識別的開發者」。這不是中毒，是 Apple 的預設保護，繞過去就能用，挑一種做法：

  • 比較簡單：先點兩下 Yobi（會被擋一次），再到「系統設定 → 隱私權與安全性」，往下捲找到被擋的 Yobi，按「仍要打開」。
  • 一勞永逸（會用終端機的話）：打開「終端機」，貼上這行按 Enter（它會要你輸入開機密碼，打字時畫面不會顯示，這是正常的）：

一般使用者抓安裝包就夠了，不用自己 build。想改原始碼、或跑最新開發版的進階使用者，GitHub 專案頁有完整的建置說明。

裝好打開，預設就能直接聊。接下來先過一遍大多數人天天會用到的基礎功能，再帶到進階一點的 Telegram 整合。

Yobi 的常用功能

一鍵把選取的文字丟給 AI

這是 Yobi 的本體。在任何程式裡反白一段文字 → 按 Alt+G → 自動送進聊天視窗 → 回應直接存成帶時間戳記的 Markdown 檔，連存檔都不用自己動手。翻譯、摘要、改寫、寫個 commit message，這種丟一段文字、要一段回應的雜事最適合它。

小提醒：要讓熱鍵隨時叫得動，記得到 設定 → 一般 → 系統匣 讓 Yobi 縮到系統匣常駐；熱鍵不喜歡 Alt+G，也可以在 設定 → 一般 → 熱鍵 自己改，macOS 預設是 Command+G。

多家 AI 隨時切換

四家 AI 都在同一個視窗裡，哪一家對某類問題比較拿手就切哪一家，不用開一堆分頁。

回應自動存成 Markdown 檔

每一次的回應都會自動存成 Markdown，並附上時間戳記。不會發生剛剛那個答案很好，結果視窗一關就找不到了的慘案。（Markdown 是一種純文字筆記格式，副檔名 .md，用記事本就能打開；這些檔案預設存在 Yobi 的資料夾裡，路徑可以在設定中查看或修改。）

反過來，有些東西你就是不想留下來。按 Ctrl+Shift+I 切到暫時對話模式，這一輪的回應完全不會寫進磁碟。

匯出成圖片或 PDF

想把某段回應分享給別人、或存成漂亮一點的檔案，可以直接匯出成 PNG、WebP 或 PDF。漸層配色、排列方向、要不要顯示原始提示詞、服務商名稱、時間戳記，都能調。

自訂語氣與提示詞偏好

每次都要在問題前面加一段「請用繁體中文、講重點」很累，所以 Yobi 把它做成設定：語氣（預設 / 專業 / 輕鬆 / 直接）、長度（自動 / 精簡 / 詳細），還有一段自訂指示會自動加在每次提示詞前面。常用的句型也能存成範本重複用。

流程：把固定步驟串成你自己的小 Agent

前面講的，都是你按一下、它就做一件事。「流程」則是把好幾個步驟串成一條會自己跑完的自動化，就像前面提過的 iOS 捷徑一樣，不用寫程式，用拖的就好。這也是 Yobi 拿來打造自己 Agent 的核心。

一條流程由三個部分組成：什麼時候觸發、中間做哪些事、結果送去哪。

觸發方式有五種，同一條流程也可以同時掛好幾種：

觸發方式說明
⌨️ 熱鍵給這條流程一個專屬的全域熱鍵
⏰ 排程每天 / 每週定時跑，設好時間就自動執行
🤖 Bot 指令自訂一個 Telegram 或 LINE 指令，例如 /news <關鍵字>
💬 聊天指令在 Yobi 的聊天框直接打 /指令 就跑
👆 手動需要的時候自己按一下執行

中間能用的技能目前有 44 種，還在陸續增加，大致分成這幾類：

類別能做的事
📥 取資料網頁、RSS、HTTP API、YouTube 字幕，還有股價、匯率、天氣，都不用金鑰
🌐 操作瀏覽器開分頁、點擊、填表單、截圖
🧠 問 AIChatGPT、Gemini、Perplexity、Duck.ai，或走 BYOK 用自己的 API 金鑰
📤 送結果傳到 Telegram 或 LINE、寄 Email、存成檔案、丟進剪貼簿
🛠️ 執行開程式、跑 JavaScript 或 shell 指令，以及系統與電源控制
🔀 流程控制迴圈、條件判斷、排程

不會排流程也沒關係，直接用白話把你要的講出來，例如「每個平日早上八點，把我的 RSS 摘要後傳到 Telegram」，AI 就會幫你把整條流程組好，之後想改哪個步驟再自己調。

這條流程配上排程觸發，就變成：每天早上自動抓我訂閱的科技新聞、用 AI 摘成三句話、推到我手機的 Telegram。我人還在睡，摘要已經躺在對話框裡了。重點是，抓資料、傳訊息這些都是固定步驟，AI 只負責中間摘要那一小段，所以跑得快、Token 也省，每天跑出來的結果也都很穩定。

不想從零開始的話，範本庫裡有 12 個現成流程可以直接套，像是 RSS 摘要推播、網站監控（盯著某個網站的新內容、AI 分析後再推播）、YouTube 訂閱摘要（把追蹤頻道的新影片摘要後連縮圖一起推給你）。選一個之後會有設定精靈帶你把該填的欄位填完，不用自己翻每個步驟。流程本身也能匯出成 .json 檔分享給別人，或從檔案、網址匯入。

用 Telegram 或 LINE Bot 遠端操控 Yobi

Yobi 可以接上 Telegram 和 LINE，這樣人不在電腦前，也能用手機叫它做事。兩邊功能是一樣的，指令設定共用，流程的 Bot 觸發器和推播步驟也都通吃；台灣這邊大家手機裡本來就有 LINE，接這個大概最順手。下面以 Telegram 為例，LINE 則是在設定裡照著兩步驟的 Webhook 引導走完就行。

設定大概三步驟：

  1. 申請一組 Bot Token：在 Telegram 搜尋 @BotFather 加入好友，按 Open 開始對話，選 Create a New Bot，再照著輸入 Bot 名稱就好，過程不難，大概三分鐘就搞定，最後它會給你一組 Bot Token（也就是 API Key）。覺得文字不夠直覺的話，這支影片把申請流程完整走了一遍：How To Create A Telegram Bot In Python For Beginners（看前面建立 Bot、拿 Token 的段落就夠了，後面的 Python 程式可以略過）。

  1. 填入 Token 啟用：到 設定 → Bots，把 Token 貼進 Telegram Bot 的欄位、按 Update Token。啟用後，下方的 Runtime Status 會變成綠色的 Running，代表 Bot 已經上線。
  2. 產生配對碼、邀請信任的人：在同一頁的 Pairing 區按 Generate Code 產生一組配對碼，把它給你信任的人；對方在 Telegram 私訊你的 Bot、傳 /start <配對碼>（或直接點配對連結）就完成配對。只有配對過的人能使喚這個 Bot，所以你也能放心把它分享給家人或同事一起用。

綁好之後，內建這幾個指令隨時能用：

指令說明
/gpt、/gemini、/pplx、/duck + 提示詞丟給對應的 AI（指令名稱可以自己改）
/output <模式>設定回覆格式（md / png / webp / pdf）
/status看一下目前狀態
/restart重新啟動 Yobi

人在外面、只有手機，傳一句 /gpt 幫我把這段話翻成日文 就解決了。懶得打指令的話，也可以設成直接對話，把訊息丟過去它就會回。

不過，像這樣把 Bot 接上 AI、問一句答一句，方便歸方便，本質上比較接近把聊天搬到手機上，還不太算得上 Agent。真正讓它有 Agent 樣子的，是搭配前面流程的 Bot 指令觸發器：同一則訊息可以帶動一整條事先排好的流程，把抓資料、判斷、輸出一次做完。能照著流程把事情交辦、做完，這一步才是 Yobi 想做到的。

設定與隱私

設定的部分就快速帶過，多半是讓它用起來更順手的選項：佈景主題（可以跟著系統深淺色走）、閱讀版面、回應逾時、開機自動啟動、關閉視窗時縮到系統匣、Markdown 字級縮放，還有完成 / 成功 / 失敗各自的通知開關。整台電腦的設定與資料可以做完整備份、換機時再還原回來，介面本身也支援 9 種語言。

另外還有一頁使用統計，執行次數、成功率、14 天趨勢圖都在上面，而且純粹在本機算，流程跑得順不順一眼就看得出來。

這裡再提兩個。一個是 Email（SMTP），設好之後流程就能把結果直接寄出來，不是每個人都想收在 Telegram 或 LINE。另一個是 BYOK：如果你手上已經有 OpenAI 相容（OpenAI、OpenRouter、Together、Groq、本地伺服器都算）或 Gemini 的 API 金鑰，可以把它加成一個額外的 AI 服務，在聊天和流程裡跟其他家一樣選用；預設仍然是走網頁，這只是多一個選項。

隱私的部分，幾個重點：Yobi 不做遙測、不收集你的使用行為，所有自動化邏輯和統計都在你自己電腦上跑；Bot Token、SMTP 密碼、BYOK 金鑰都會交給作業系統內建的加密保險箱（Windows 的認證管理員、macOS 的 Keychain）先加密再寫進磁碟。你問 AI 的內容會送到對應服務商、受各家隱私政策約束，這些平台都不在作者的掌控範圍內。整個專案是開源的，所有邏輯都攤在 GitHub 上，想確認的話都能自己看。

結論

做 Yobi 的初衷，就是想把建立自己的 AI Agent 這件事的門檻降到最低。不用先砸一筆錢買能跑大模型的機器，也不用一開始就綁卡被收費，把本來就登入好的網頁接起來，再用流程把固定步驟排一排，日常那些瑣事其實就能自己跑完。而且因為 AI 是在固定流程下才被呼叫，結果是可預期的，不會今天好好的、明天突然歪掉。

Yobi 也無意取代 OpenClaw、n8n 那種完整平台；它想做的，是讓你在手邊有限的資源裡，把簡易自動化加上 LLM 這件事先做起來。

如果你也想到其他不錯的應用、或對 Yobi 有任何建議，都歡迎到 GitHub 開 Issue 一起討論；想自己改、或好奇它底層怎麼疊的，原始碼也都在上面。

如果 Yobi 對你有幫助、想支持我繼續做下去，可以到贊助頁面請我喝杯咖啡，或直接到 GitHub 幫專案點顆 ⭐。這些都會讓更多人看到它，也是我繼續更新的動力。
