看起來很懂 AI 跟真的懂 AI 是兩回事

AI 進到職場後，講得好聽跟做得出來的距離被拉得更開。從用術語堆出來的權威感、剛學會就急著看不起同事，到把 AI 使用率當 KPI、用 Agent 燒 Token 做 API 幾行就能解決的事，整理幾個常見的 AI 話術陷阱，也聊真正的技術判斷是知道什麼時候不該用 AI。

前言

AI 進到職場之後，聽起來很懂跟真的懂之間的距離，好像被拉得比以前更開了。以前想在會議上撐出技術權威感，好歹得把術語念熟、把流程走過一次；現在只要丟得出幾個英文縮寫，就能先把架式擺出來。

架式擺得出來，不代表東西做得出來。整理幾個我在職場上反覆看到的模式，用術語堆城牆的，跟用 AI 堆優越感的，套路不一樣，底層邏輯卻是同一套：先把姿態做足，交付的事之後再說。

底下這些故事大多是聽來的，講的也是一種到處都看得到的現象，當個參考就好。真要讀到哪一段覺得刺，很多時候不是那個人本性如此，是上面的要求逼出來的，甚至是不演不行的場面話。

術語是護城河還是遮羞布

有種人講技術時，會三不五時拋出艱深卻與討論無關的說法，讓人一愣，說不出那跟眼前的問題有什麼關係；真要他把事情講清楚，又講不出所以然。那種感覺不像是想說明白，更像是要提醒大家，他懂的比檯面上看到的多。

會做不會講的工程師是另一回事。這種人剛好相反，只會講、不會做，甚至連方向都是錯的。真正需要拍板、扛結果時，他反而第一個跳出來說做不到：文件爛、需求不清。聽起來像把關品質，實際上是先把期望壓低，交出點東西就算超標，搞砸了也早有理由可以推。

討論到一半，還會用看好戲的姿態插進來，笑別人討論的東西幼稚。內容其實沒什麼問題，他只是想讓自己站在旁觀、比較高的位置。

說到底，這種人設成本很低：詞彙夠新、夠密集，大部分人來不及查證，就先把權威讓出去。可是一旦要交付，這套詞彙撐不住，因為做不出來的東西，講得再漂亮也生不出結果。

剛學會用 AI 就急著把別人比下去

更常見的是剛開始用 AI 沒多久，就覺得自己看到了別人看不到的東西。效率確實有提升，但這種提升被放大成一種身分認同，開始看不起還在用老方法的同事，覺得對方跟不上時代。

這就是鄧寧－克魯格效應：一個人剛入門、程度還薄的時候，最容易高估自己，因為連自己不懂什麼都判斷不出來，得深入下去才會發現一開始的自信有多廉價。剛學會用 AI 的人，很多卡在這個階段，把它當成天賦，忘了這只是個會過去的階段。

這種自信最後會長出一些嚇人的說法。我聽過最極端的一句是，AI 產出來的程式碼不用看，反正跑得起來就好。講這句話的人，多半根本不知道自己在幹嘛，以為方向盤本來就可以整個交給 AI 開。但程式碼能跑起來，跟程式碼是對的，從來是兩件事，這中間的差距要有一定程度才看得出來，看不出來的人，正好也是最敢講這句話的人。

那種爽感不是錯覺。AI 給出回應的瞬間會觸發多巴胺，機制跟吃角子老虎機很像，你永遠不確定這次會不會得到特別好的答案，這種不確定感讓人一次次想再按。爽感是真的，只是跟工作真正的產出是兩件事。

但職場的薪資結構從來不是這樣算的。隔壁那個完全不碰 AI、方法老派的資深同事，薪水可能還是比較高，因為決定薪水的是年資、位置，還有跟公司談判的籌碼，會不會下 prompt 排不進去。把 AI 用得順當成職場地位上升的證據，某種程度上是搞錯了因果。更諷刺的是，他們一個月的薪水，夠訂閱至少五份 Claude Max 20x，做出來的東西不見得比你少。真正墊高身價的，搞不好是那幾份訂閱。

而且這種人講的內容，往往是網路上找得到的東西，講久了自己都以為是第一手心得。這兩種人設也不互斥，現實中更常見的是同一個人身上兩種都有，只是比例不同。

你怎麼知道自己飛的是最短路徑

前陣子我拿一個很單純的問題去問 AI：台灣飛舊金山，最短的路怎麼走。它答得很漂亮，大圓航線、噴射氣流、阿留申群島南側、一萬四百公里、東行順風十一小時，該有的名詞一個都沒少。我追問，為什麼不往西飛？往西當然也到得了，只是等於繞地球另一邊回來，是三萬公里等級的距離，不是一萬出頭。

麻煩在這裡：往西飛，最後真的會到。幾乎每個航向都會到，繞遠路是到，用三倍油繞掉大半個地球也是到，儀表全程都顯示你在前進。真正的問題從來不是能不能到，是你怎麼知道自己走的是最短那條，而不是在繞路。這個問題 AI 幫不了你，因為它給的每條航線，聽起來都一樣有把握。

機長如果沒有判斷是非的能力，這件事就整個反過來：AI 說可以，你就覺得可以；它說不行，你就真的不做。表面上航向是你在下，實際上是它在下。這種盲區雙向：一邊是它把繞遠路講得像最短路徑，另一邊是權威口吻說做不到，你就真的信了。不懂的人根本不會發現有錯，因為他連自己該不該懷疑都不知道。

第二種我前陣子就遇過。某平台新版硬體，我們想用的一項功能，我丟給 AI 查，它翻到原廠技術支援頁面，回得很乾脆：不支援，範例裡也找不到。AI 查證說穿了就是搜尋加翻文件，事實沒有錯，只是停在查得到的地方；判斷力不夠，很容易把不支援當成結論。但那功能不是硬體做不到，只是原廠沒包成現成的東西；對底層夠熟，繞開官方範例一樣拿得到結果。原廠說的是不提供，不是不可能，這兩句話差得很遠，能不能分辨，靠的是你對底層懂多少，跟 AI 查得多仔細沒關係。所以方向對不對，往往查不出來，得看你信不信這件事做得到，會不會做。

寫程式最容易看到後果。同一套工具，有人拿它把想清楚的架構做得更快，有人拿它把還沒想清楚的東西大量生出來，工具一樣，差在動手的人理解有多深。前面那句 AI 產的程式碼不用看，就是這樣飛出去的：系統爛得很快，而且爛在看不到的地方，等到要接手、要改、出事，才一次還給你，多半已經到了打掉重練的地步。

副駕駛可以幫你握操縱桿、唸檢查表，做得比你快也穩。但航向是機長決定的，飛錯了機長扛。如果連要往東往西都得問副駕駛，那就是在賭。攤平的地圖上，看起來最直的線，往往不是最短的；看起來最順手的 AI 用法，也常常不是。

把 AI 使用率訂成 KPI 就成了一場表演

這種職場環境一旦被 KPI 接住，就會整個走鐘。問題的根源，往往是訂 KPI 的那個人自己不懂技術：他判斷不了一個團隊有沒有因為 AI 而做出更好的東西，那太難量，而且需要他真的看得懂內容；相對的，用量是他看得懂、也考核得出來的數字。講白一點，把 AI 使用率訂成 KPI 本身就是很蠢的事，它量的是投入，不是產出。當一個指標變成目標，它就不再是個好指標。

而數字一旦變成目標，底下的人就會照著數字最佳化。要把用量衝上去，最快的辦法就是大量生產沒有意義的東西，反正沒有人會回頭檢查那些產出到底有沒有用，只要 Token 有燒掉、用量有跳動，數字就好看。

其中最好笑的，是拿最貴的模型去做最瑣碎的事。切一個 git branch，指令十幾個字元，按下去零點幾秒就結束，但為了讓用量好看，這種事也值得開一個新對話、把 repo 目前的狀況交代一遍、等 Claude Opus 4.8 慎重思考個幾秒，最後在背後鄭重其事地執行一行 git checkout -b，把 branch 切好。一個拿去解奧林匹亞數學題都不算浪費的旗艦模型，就這樣被派去替一個大概連 git 都不會的人切一條 branch。反正這週的使用率又往上跳了一格。

還有一種更直接的玩法：故意把額度用爆。像 Claude 這種以五小時為一個區間的用量上限，只要刻意衝滿，接下來就進入冷卻，什麼都動不了。額度爆掉，工作自然也做不下去了，而使用率那條線，還是漂漂亮亮地往上。

稍微有底子的人看到這種用法，第一個念頭大概不會是這個人很懂 AI，而是他連自己在幹嘛都不知道。但主管看不出這個差別，他唯一能依據的就是誰看起來最擁抱 AI，於是最會演的那個，反而成了他眼中最跟得上時代的員工。上面看不懂，下面就知道要演給誰看，劣幣驅逐良幣通常就是這樣開始的。演久了還會拉著別人一起演，看到同事正專心處理一件事，也要探頭問一句怎麼不先問 AI。

這種公司現在還多的是，整個組織活在一種期望膨脹的狀態裡，好像只要沾上 AI 兩個字，什麼決策都自動變得比較正確、比較先進。最後就變成，用不用 AI 比做不做得出結果更重要。KPI 要的就是一個漂亮的用量數字；而底下交出去的，也就真的只有數字，還有數字底下那一堆沒人想看的垃圾。

當 AI slop 被包裝成商品拿出來賣

前面講的都還在公司內部，衝著 KPI 生出來的垃圾，至少爛在自己家裡。比較誇張的是，同一批東西現在被包裝成產品，標上一個嚇人的價格，拿到市場上賣。

網路上有個詞叫 AI slop，指用 AI 大量灌出來、品質低落又沒什麼人真的需要的內容，原本講的是文章跟圖片，現在連整間公司、整套服務都能這樣灌。我看過一個很典型的例子：一間主打 AI 全端開發的公司，首頁掛著一整排 AI 部門，每個配一個 Agent，從技術到法務財務分工到齊；作品區好幾十個專案，從醫療、玄學排到虛擬展間，八竿子打不著的領域全湊在一起；技術堆疊那一排也密密麻麻，多到讓人來不及一個個查。

但這種東西最麻煩的地方在於危險。他們主打的那個客製 AI Agent，說穿了就是把一個大型語言模型接上後端，接得毫無防備。我看過實際被玩壞的過程：幾句話就能讓它繞開原本的角色設定，把整台主機當成自己的殼在用，跑出來的結果全是真的，不是模型在演。權限一路墊到 root，最後連主機上那份 Claude 的憑證檔案都讀得出來。

他們官網上還特別掛著一行 AI 成本 0 元。一把付別人錢的鑰匙就這樣敞在那，誰問都碰得到，也難怪它敢寫 0 元：反正燒的從來不是自己的錢。一個對外開放、可以被提示詞注入、後面還接著 root 權限跟明文金鑰的聊天機器人，就是這樣一件標價一萬二的商品。

這剛好把整篇想講的東西攤在檯面上。它看起來什麼都有，一排部門、幾十個專案、最新的框架，但做出來的人根本不知道自己把什麼接上了什麼。姿態做到滿，底下是一個你問什麼它答什麼、順手就把金鑰交給你的東西。技術判斷缺席到這個地步，還能包裝成商品賣出去，才是最讓人不安的地方。

動手之前，先看看別人怎麼做

前面這些說到底都是同一個破洞：不知道什麼時候該用 AI，也不知道什麼時候不該用。

學術上做研究，第一步是文獻回顧，不是動手寫：前人做過什麼、走到哪裡、卡在哪裡，弄清楚了，才輪到你說自己想改善什麼、想解決什麼問題。工程上其實是同一回事，同樣的問題別人怎麼實作、踩過哪些坑、最後為什麼選了這條路，看過一輪之後再動手，通常比從零開始自己想更快，也更穩。有前人的路可以借鑑，你至少知道自己現在站在哪裡。

但很多人把這一步整個跳過去，一句話直接丟給 AI 處理：現在只要丟一句話給 AI，它就能生出一份看起來很完整的架構、流程、計畫，排版漂亮、步驟分明，唯一的問題是那份東西沒有被驗證過。它看起來可以跑，不代表它真的成立。要確認它成不成立，還是得你自己去查、去試、去撞牆，而這一段沒有捷徑，該花的時間跟力氣一分都少不了。出一張嘴、一句話丟給 AI 直接實作，省下來的只是打字的時間，該踩的坑一個都不會少。

但這一步有前提，你得先有一定的底子。不然別人講的東西，你根本沒有能力判斷對錯，看再多資料也只是照抄，抄到錯的也不會發現。

原則就是把機械式、可以固定下來的步驟先排好，只把真正需要判斷的那一小段交給 AI，這樣跑起來才快，Token 用量也不會爆炸，結果還可以預期。反過來看，用 Agent 一步步點滑鼠，去做一件原本用 API 或 MCP 串接就能穩定解決的事，跟前面拿旗艦模型切 git branch 是同一種浪費：流程一樣做完，代價卻是好幾倍的時間跟 Token，換來的還不見得比較穩定。

會做這種選擇，通常不是因為真的評估過成本，而是因為用 AI 做這件事本身，比把事情做完更重要。跟前面那個死守術語的人一樣，姿態擺在產出前面。

結論

判斷一個人是不是真的懂，方法其實很簡單：讓他把東西講給完全不懂的人聽，然後多問幾句。真懂的人，通常三兩句就能講到重點，講不清楚的時候也會老實說不確定；只靠人設撐著的人，一被追問細節，要嘛開始繞，要嘛開始不耐煩。

不懂其實沒什麼，沒有人一開始就懂。真正麻煩的是不懂又要裝懂，然後趁著旁邊的人也不懂，用氣勢把場面撐過去。這種撐法騙得過一次、兩次，撐不到第三次。前面那種一天到晚說這個不行、那個不行的人，說真的，同樣的事交給 AI 做，搞不好都比交給你好。

底子這種東西藏不住，原因就在這裡。AI 可以幫你生出一份看起來很完整的東西，但它生不出你的理解。東西可以是它寫的，被問到的時候，站在那裡的人是你。而那一秒答不出來，前面講過的術語、衝出來的用量，一個都救不了你。

而基本功都藏在很細的地方。git 就是個好例子，其實沒有想像中難，日常九成以上的操作就是 commit，但有人光看到指令列就先退縮，也有人以為 git 只有指令這一種用法，不知道圖形介面和擴充套件都是現成的。工具從來不是問題，願不願意花一個下午把它摸熟才是。

而我聽過最誇張的一次，是有人以為 git 是 Claude 的東西。

還有一種，是把不用 IDE 當勳章。有人主張寫程式根本不用 IDE，開個終端機把 AI 跑起來就夠了，好像少開一個視窗，功力就自動高一階。但跳轉定義、除錯器、差異比對這些東西，本來就是拿來看懂程式用的，把它們全丟掉的人，通常也正好是最不去看程式的那一群。這不是 AI 幫得上忙的地方。它跟知識無關，純粹是有沒有真的動手做過。

至於自己該怎麼做，我想來想去也就那幾件：話少講一點，事多做一點，要下結論的時候盡量拿得出具體的證據。真正把 AI 用出效益的人，多半話不多，因為省下來的時間都拿去做別的事了。

我大概還是會繼續用最笨的方法分辨：不看誰講得多精彩，看誰東西真的做得出來。
