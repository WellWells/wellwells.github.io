在本地端加入 Notion MCP：三步驟接進 Claude Code、Codex、Antigravity

三步驟把 Notion MCP 接進 Claude Code、Codex、Claude Desktop 與 Antigravity：加一行設定、走 OAuth 授權就自動連上，不用架伺服器或裝套件，說明在意隱私時為何該把 MCP 裝在本地端。

什麼是 MCP？為什麼別直接用網頁版連 Notion

要讓 Claude、ChatGPT 這類工具能讀寫你自己的 Notion，靠的是模型上下文協定（model context protocol，MCP），一套讓 AI 工具連上外部服務的開放標準。

最省事的是用網頁版，ChatGPT 網頁版、Claude 網頁版都能一鍵用 OAuth 連 Notion。但它有個隱私上的缺點，這條連結是綁在你登入的那個帳號上。如果你的 AI 帳號跟家人共用，那任何人用這個共用帳號，都能透過 AI 讀到你 Notion 裡的東西。

改成把 MCP 加進你自己電腦上的工具（Claude Code、Codex 這些）就沒這問題，授權只存在你這台機器的設定檔裡，別人用共用的網頁帳號登入也碰不到；而且授權時你可以只勾要開放的頁面，其餘一概看不到。

聽到 MCP、伺服器這些字先別緊張，你完全不用自己架伺服器、也不用裝任何額外套件。這裡走的是 Notion 官方託管的 MCP，用 OAuth 授權，加一行設定、跳瀏覽器點一下同意，工具就自己接上了。

Claude Code 連 Notion MCP：OAuth 三步驟設定

Notion 連 MCP 有兩種驗證方式：OAuth 和個人存取權杖（personal access token，PAT）。這篇以 OAuth 為主，因為它最貼近官方推薦的做法，連的是 Notion 自己託管的伺服器，本機不用裝也不用跑，額外套件一個都不必維護，授權跳個瀏覽器點一下就好。

第一步：一行指令加進 Claude Code

加設定就一行，用 HTTP transport 指到 Notion 官方的 MCP 網址：

1

claude mcp add --transport http notion https://mcp.notion.com/mcp

它會回你已寫進本機設定檔：

1
2

Added HTTP MCP server notion with URL: https://mcp.notion.com/mcp to local config
File modified: /home/wells/.claude.json [project: /home/wells]

這行只是把要連哪個網址記進本機設定檔（~/.claude.json），還沒真的授權。沒特別指定的話，範圍只在這個專案生效；想每個專案都用，加個 -s user。

第二步：開 Claude，跑一次瀏覽器授權

設定加進去後，在終端機打 claude 啟動 Claude Code，一開起來就會看到提示要你驗證：

1

⚠ 4 MCP servers need authentication · run /mcp

在對話裡打 /mcp，會看到 notion 標著需要驗證，選它：

1
2
3
4
5

Manage MCP servers
   9 servers

     Local MCPs (/home/wells/.claude.json [project: /home/wells])
   ❯ notion · △ needs authentication

選下去它會開瀏覽器跑 OAuth（瀏覽器沒自動開，就手動複製那條網址）：

1
2
3
4
5
6
7
8
9

Authenticating with notion…

  ✻  A browser window will open for authentication

  If your browser doesn't open automatically, copy this URL manually (c to copy)
  https://mcp.notion.com/authorize?response_type=code&client_id=...

  If the redirect page shows a connection error, paste the URL from your browser's address bar:
  URL > http://localhost:3118/callback?code=...

如果你像我一樣是透過 SSH 把 Claude Code 跑在遠端主機上，最後那行 URL > 就派得上用場。授權完 Notion 會把你導回 http://localhost:3118/callback?code=...，但這個 localhost 指的是你本機瀏覽器所在的電腦，不是遠端那台在等回呼的 Claude Code；我也沒把 3118 埠用 SSH 轉發過去，所以那頁只會顯示連線錯誤。這時把瀏覽器網址列那條完整網址複製起來，貼回 console 的 URL > 送出，就把授權碼交回遠端了。直接在本機跑 Claude Code 的話不會遇到，瀏覽器會自動接回去。

在瀏覽器點同意時，會讓你選要開放哪些頁面，這一步就是你控管它能看到什麼的地方，只勾你要給的，其餘一概碰不到。

第三步：確認連線成功

授權完，終端機會回：

1
2

/mcp
  ⎿  Authentication successful. Connected to notion.

看到 Connected to notion 就成功了，之後每次開 Claude Code 都會自動接上，不用再手動啟動任何東西。想收回授權，在 /mcp 裡選 notion 斷線就好。

Codex、Claude Desktop、Antigravity 怎麼連 Notion MCP

一句話講完，底層都是連 Notion 官方託管的那個 MCP、都用 OAuth 授權，加完也都會自動載入，差別只在加設定時是打指令、貼一段設定、還是在選單裡點一下；四個都不用裝額外套件。

工具怎麼加設定怎麼授權
Claude Code終端機跑一行 claude mcp add 指令打 /mcp 選 notion，跳瀏覽器
Codex CLI（ChatGPT）在 ~/.codex/config.toml 加一段 notion 設定跑 codex mcp login notion，跳瀏覽器
Claude DesktopSettings → Connectors 搜尋 notion 加入，不用貼網址、綁帳號當場跳瀏覽器
Antigravity在 ~/.gemini/config/mcp_config.json 加一段 notion 設定重新載入後跳瀏覽器

Codex CLI（ChatGPT 的終端機版） 雖然有 codex mcp add 指令，但它只吃本地 stdio 伺服器（-- 後面要接一個啟動伺服器的指令）；Notion 官方 MCP 是一條遠端網址，套不進這個指令。遠端伺服器官方的做法是改設定檔 ~/.codex/config.toml，加上這段：

1
2

[mcp_servers.notion]
url = "https://mcp.notion.com/mcp"

存檔後跑 codex mcp login notion，一樣跳瀏覽器授權。（部分 Codex 版本把遠端 MCP 當實驗功能，如果連不上，先在 config.toml 加一個 [features] 區塊、設 experimental_use_rmcp_client = true 再試一次。）

Claude Desktop 更省事，連設定檔、網址都不用碰。到 Settings → Connectors 直接搜尋 notion、點加入，當場完成 OAuth 就好（這功能限 Pro／Max／Team／Enterprise）。

不過 Claude Desktop 的連接是綁在你的 Claude 帳號上，會同步到你登入的每個裝置（連網頁、手機都算），不像 Claude Code、Codex 只留在本機設定檔。也就是說，任何人登入這個帳號都能透過它讀到你的 Notion。如果你的 Claude 帳號跟家人共用，就別用這條綁，改用前面 Claude Code 那種只留在本機的做法。

Antigravity 設定檔在 ~/.gemini/config/mcp_config.json（IDE 版和 CLI 版共用），加一個指到網址的伺服器：

1
2
3
4
5
6
7

{
  "mcpServers": {
    "notion": {
      "serverUrl": "https://mcp.notion.com/mcp"
    }
  }
}

貼進去、重新載入，同樣跳瀏覽器授權。介面上可以到 Settings → Customizations 找到開啟這個設定檔的按鈕。

用個人存取權杖（PAT）連 Notion

如果你的情境是無人自動化，或想連伺服器都跑在自己機器上、把權限收到單一頁面，Notion 也有靜態的**個人存取權杖（personal access token，PAT）**可以用。到開發人員頁面建一個連接、驗證方式選 Access token，就會拿到一把 ntn_... 開頭的 key。接著在 Claude Code 用這把 key 接本地的 Notion MCP server：

1

claude mcp add notion -e NOTION_TOKEN=ntn_你的_token -- npx -y @notionhq/notion-mcp-server

這裡跑的 @notionhq/notion-mcp-server 是在你機器上本地執行的伺服器。要注意的是，Notion 目前只積極維護遠端那台官方 MCP，這個本地 repo 已經不太更新，所以還是建議優先用前面的 OAuth 做法。

結論

把 Notion 接進 AI 工具其實沒那麼難，加一行設定、瀏覽器授權就接上了，不用架伺服器也不用裝套件。各工具只差在設定方式，底層連的都是 Notion 官方那個 MCP。接好之後，就能直接在 CLI 裡請 Claude 或 Codex 幫你寫 Notion 筆記，或是本地分析完一份 PDF、直接把結果寫進 Notion，我個人覺得蠻方便的。

會想這樣接、而不用網頁版一鍵連，最實際的理由還是隱私。像 Claude Code 這種把授權留在本機設定的做法，頁面你自己挑，帳號就算共用也只有你碰得到（Claude Desktop 綁帳號是例外，共用帳號就別用它綁）。所以在意隱私的話，我會建議盡量把 MCP 接在本地端。而且值得在本地裝的 MCP 不只 Notion，開發時常用的還有 Context7、Playwright MCP、Chrome DevTools MCP、GitHub 官方 MCP Server 等等；把這些在本地一個個串起來，就能讓 Claude 或 Codex 用到更多工具、拿到更精準的資訊，一次做更多事。
