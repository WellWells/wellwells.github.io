Tailscale 進階應用教學：Taildrop、出口節點與子網路路由設定

Taildrop 檔案分享、出口節點（Exit Node）與子網路路由（Subnet Routing）的設定方式：怎麼在裝置之間互傳檔案、把流量改走指定節點，以及讓外網裝置連進內網服務。

引言

在上一篇《使用 Tailscale 輕鬆建立安全且私密的隧道》中，我介紹了 Tailscale 背後的原理、如何安裝 Tailscale 以及兩台電腦之間的連線。這篇往下講 Tailscale 的進階應用，包括 Taildrop 檔案分享、出口節點（Exit Node）設定 以及 子網路路由（Subnet Routing）配置。這些功能可以做到內網穿透與遠端存取，存取權限也比自己設一堆防火牆規則好管理。

這些不只適用於企業環境，個人使用者也可以用 Tailscale 把 NAS、影音串流等內網服務整合起來，人在外面一樣連得到、管得動。

舉一些簡單的例子如：

  1. 如何將裝置 A 中的檔案或是照片，安全且高效地傳輸至裝置 B？
  2. 如何讓裝置 B 借道裝置 A 連上網際網路，解決部分網頁無法存取的問題？
  3. 裝置 A 可連線至 NAS（IP 位址為 192.168.88.88），位於外網的裝置 B 如何能透過此 IP 位址連線到 NAS？

這些議題將在後續章節中進一步討論與說明。

先確認至少有兩台裝置已成功安裝 Tailscale。在 Windows 系統中，執行 命令提示字元（CMD） 並輸入以下指令：

tailscale status

使用 Taildrop 傳遞檔案

Taildrop 可以在兩個裝置之間互傳檔案或資料，概念類似 Apple 裝置上的 AirDrop。差別在於 AirDrop 主要依賴 Wi-Fi 或藍牙，Taildrop 走的是 Tailscale 的安全加密通道，不受裝置距離限制。

啟用 Taildrop

Taildrop 目前仍處於 Alpha 階段，需要手動啟用才能使用該功能：

  1. 登入 Tailscale Admin Console
  2. 進入 Settings > General
  3. 找到 Send Files（傳遞檔案） 選項，並開啟 Taildrop 功能。

傳遞檔案

要把手機上的檔案傳送至其他裝置，先選取要傳送的照片或檔案，點選分享選單，並選擇 Tailscale。系統會顯示可傳遞的目標裝置，選好之後即可開始傳輸。檔案傳送完成後，會自動存放於 目標裝置的下載目錄 中。

從電腦傳檔案到 iPhone、Mac 或是 Android 裝置上也很簡單，對檔案右鍵 → Send with Tailscale...，就可以在其他裝置上取得檔案。

傳遞檔案到 NAS

Synology NAS 預設並無下載資料夾，要先手動建立一個新的共用資料夾，並命名為 Taildrop。接著給系統內的 tailscale 使用者該資料夾的讀寫權限，設定完成後就能用 Taildrop 把檔案傳到 NAS。

  1. 建立共用資料夾
    • 進入 Synology 控制台 > 共用資料夾 > 建立
    • 設定資料夾名稱為 Taildrop
    • 略過加密及進階設定

  1. 設定 tailscale 使用者權限
    • 於權限設定畫面中，顯示內部使用者帳號
    • 找到 tailscale 使用者賦予完整存取權限

  1. 完成設定
    • tailscale 有讀寫權限之後，就能用 Taildrop 把檔案傳到 NAS，傳輸後的檔案會存在 Taildrop 資料夾。

Linux 傳遞檔案

在 Linux 上傳輸檔案，我通常會使用 SCP + SSH。但若伺服器未啟用 SSH，也可以改用 Taildrop。

在操作 Tailscale 指令，如果未設定 Tailscale 的 operator，每次執行指令時都需要使用 sudo 提升至系統管理員權限。為了簡化操作，可以設定 operator，讓目前使用者擁有 Tailscale 操作權限，避免頻繁使用 sudo 來執行 Tailscale 指令：

1

sudo tailscale set --operator=$USER

在 Linux 上，可以使用 tailscale file cp 指令來傳送檔案，格式為：

1

tailscale file cp [檔案名稱] [目標裝置]:

指令結尾的冒號 (:) 是 Tailscale 規定的格式。例如，傳送 gen_cert.sh 檔案至 wells_home 裝置：

1

tailscale file cp gen_cert.sh wells_home:

執行後的輸出結果如下：

1
2

wells@server:~$ tailscale file cp gen_cert.sh wells_home:
gen_cert.sh     1.65KiB     1.02KiB/s     100.00%     ETA 00:00:00

若要接收檔案，可先在裝置 A 透過 Taildrop 在電腦上傳檔案至伺服器，然後在 Linux 上執行以下指令，將檔案存入目前目錄 (.)：

1

tailscale file get .   # . 表示接收檔案儲存在目前目錄

使用 Tailscale 設定出口節點來轉送流量實現翻牆

有些情境會想把所有或部分網路流量改走特定裝置，例如：

  1. 出差到國外，無法正常連線至特定網站或服務（如 ChatGPT）。
  2. 某些網頁透過 IP 位址確認裝置是否為特定機構才能存取，但目前裝置不在內部網路。
  3. 想要加強隱私保護，讓流量走可信任的裝置，而非直接使用公共網路。

我先前出國買的部分 SIM 卡會漫遊到香港，香港目前會受到 ChatGPT 的限制而無法正常使用。這時候設一個出口節點，選臺灣或其他地區的伺服器，就能繞過限制。

設定出口節點

使用出口節點相當簡單，首先需將目標裝置設定為出口節點。

在 Windows 和 macOS 上，可以右鍵點選圖示，然後選擇 Exit nodes → Run exit node...。

在 Linux 上，則需先啟用 IPv4/IPv6 轉發，執行以下指令：

1
2
3

echo 'net.ipv4.ip_forward = 1' | sudo tee -a /etc/sysctl.conf
echo 'net.ipv6.conf.all.forwarding = 1' | sudo tee -a /etc/sysctl.conf
sudo sysctl -p /etc/sysctl.conf

由於 Tailscale 已經啟動，只需附加 --advertise-exit-node 旗標，即可將裝置設定為出口節點：

1

sudo tailscale set --advertise-exit-node

在裝置端宣告為出口節點後。接著，進入 Tailscale Admin Console，在路由設定中啟用 Use as exit node。

連線出口節點

設定完成後，其他裝置（例如手機）可以透過 Tailscale 連線，並選擇出口節點。選擇出口節點後，可以透過 Cloudflare Radar 檢查 IP 位址 或是於終端機中輸入 curl checkip.amazonaws.com 取得 IP 位址，確認是否已變更為出口節點裝置（server-1）的 IP 位址。

Linux 系統可以用以下指令連線出口節點：

1

tailscale set --exit-node=100.100.57.95

之後所有流量都會走所選的出口節點，在有網路封鎖的地區就能繞過限制。

使用 Tailscale 子網路路由

在企業或個人網路環境中，部分裝置（如 NAS、伺服器、印表機等）無法直接安裝 Tailscale，此時可透過 子網路路由（Subnet Routing） 存取這些內部裝置。Tailscale 允許特定裝置充當 閘道器（Gateway），讓其他裝置透過該閘道存取整個內部子網路。

宣告子網路

假設裝置 A 與內部路由器（IP 位址：192.168.100.1）可直接通訊，若希望裝置 B 也能透過 Tailscale 存取該網頁服務，則可在裝置 A 上宣告子網路。在系統中執行終端機，輸入以下指令：

1

tailscale set --advertise-routes=192.168.100.0/24

以上範例中的 192.168.100.0/24 採用 CIDR 表示法，對應的 IP 位址範圍為 192.168.100.0 ~ 192.168.100.255。

如果只需共享 192.168.1.1 ~ 192.168.1.10，就必須在指令中以 CIDR 表示法分段指定：

1

tailscale set --advertise-routes=192.168.1.1/32,192.168.1.2/31,192.168.1.4/30,192.168.1.8/31,192.168.1.10/32

可使用 CIDR 計算機 找出最佳化的 IP 位址區段設定。

在 Linux 系統上，需要另外啟用 IPv4/IPv6 轉發功能，執行以下指令：

1
2
3

echo 'net.ipv4.ip_forward = 1' | sudo tee -a /etc/sysctl.conf
echo 'net.ipv6.conf.all.forwarding = 1' | sudo tee -a /etc/sysctl.conf
sudo sysctl -p /etc/sysctl.conf

完成子網路宣告後，進入 Tailscale Admin Console，在對應裝置的路由設定中啟用 宣告的子網路：

設定完畢後，Tailnet 內的所有裝置即可存取 192.168.100.xxx 下的裝置。例如在 Windows 系統下 ping 一次看看：

使用系統連接埠轉發

除了用 Tailscale 宣告子網路，也可以直接用系統內建功能做連接埠轉發。例如 Windows 用 netsh、Linux 用 iptables 將外部連接埠導向內部裝置。但如果想把存取權限管得細一點，對不同子網路的使用者也要能分開控管，還是建議優先採用 Tailscale 子網路路由。Tailscale 本身的存取控制（access control lists，ACL）可以更輕鬆指定哪些裝置能夠連線到目標子網路，避免繁雜的防火牆與轉發規則設定。

Windows 系統轉發

以 Windows 為例，在系統管理員模式下執行終端機後，用以下指令把外部 9999 連接埠轉發至 192.168.100.1 的 80 連接埠：

1
2

# 新增路由，[裝置名稱:9999] 轉至 [192.168.100.1:80]
netsh interface portproxy add v4tov4 listenport=9999 listenaddress=0.0.0.0 connectport=80 connectaddress=192.168.100.1

如果要刪除規則，指令如下：

1
2
3
4
5

# 刪除路由
netsh interface portproxy delete v4tov4 listenport=9999 listenaddress=0.0.0.0

# 刪除所有 portproxy 規則
netsh interface portproxy reset

新增路由後，使用者只需輸入 http://server-1:9999，便可看到該 Web 服務。若要檢視所有路由規則，可執行以下指令：

1

netsh interface portproxy show all

範例輸出結果：

1
2
3
4
5

位址            連接埠      位址            連接埠
--------------- ----------  --------------- ----------
0.0.0.0         9999        192.168.100.1   80

若電腦安裝了其他防火牆或防毒軟體（例如 Bitdefender），需在防火牆規則中允許連接埠 9999 的傳入或雙向連線：

Linux 轉發

在 Linux 系統中，也可以用 iptables 做路由轉發。下列指令需在系統管理員模式下執行：

1
2
3
4
5

# 1. PREROUTING: 將來自外部的 TCP 80 連接埠請求，轉發到內部 192.168.0.22:3000
iptables -t nat -A PREROUTING -p tcp --dport 80 -j DNAT --to-destination 192.168.0.22:3000

# 2. POSTROUTING: 確保回應的封包回到請求者
iptables -t nat -A POSTROUTING -p tcp -d 192.168.0.22 --dport 3000 -j MASQUERADE

確認規則是否生效：

1

iptables -t nat -L -v -n

成功後，應會看到類似下列輸出：

若系統啟用了防火牆（例如 ufw），記得開啟 80 連接埠號的傳入流量：

1
2
3

sudo ufw allow 80/tcp
sudo ufw reload
sudo ufw status

這樣就能用 Tailscale 裝置名稱 + 連接埠號存取特定的服務。

結論

連接埠轉發用 Windows netsh 或 Linux iptables 都做得到，但我還是會優先用 Tailscale 內建的子網路路由，ACL 規則寫起來比一條一條設防火牆快得多。如果需要限定特定裝置才能存取子網路，可以參考 Manage permissions using ACLs，官方文件寫得很完整。

最後補一個工作機上常用的做法。多數工作用 Windows 筆電配備雙網卡（有線與無線網路），把 fMinimizeConnections 設為 0，電腦就能同時連接 Wi-Fi 和有線網路。接著用 route 指令做子網路分流，預設所有流量走無線網路（外網），172.x.x.x 或 192.x.x.x 這些內部子網路則導向有線網路。要注意的是，這種方式繞過內網限制可能帶來安全風險，務必謹慎評估是否真的有這些路由需求。
