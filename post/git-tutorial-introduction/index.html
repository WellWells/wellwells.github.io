前言

本系列 Git 教學將著重在 VS Code 與 Git 的操作、整合與專案管理。

什麼是版本控制？

版本控制是隨著時間用來追蹤檔案的差異與變化，並且可以儲存、回溯到特定版本。

像是 Google Sheet、微軟 Microsoft 365 (Word、PowerPoint、Excel) 都提供歷史版本檔案的回溯：

有了軟體本身的歷史紀錄，就不需要把檔案複製一份來備份，最後留下一堆檔案。

版本控制如果是文字檔案，還可以比對檔案之間的差異。像是說明 test.txt 從 A 版本變為 B 版本新增或刪除了哪些東西，這就是版本控制的目的。

而要管理像是文字檔案（txt, c, py, js, md 等...），繪圖檔案(psd, ai)、模擬檔案等...。

常見、主流且是業界標準的軟體有：Git 與 Subversion（SVN）。

兩者皆為開源、免費。可以裝在私人電腦或公司電腦上管理檔案、專案。

什麼是 Git？

Git 是一個分散式版本控制系統（version control system，VCS）。

每個成員都可以將完整的程式碼從遠端儲存庫(remote repo(sitory))複製（clone）到本地端（local repo）。

多個成員 clone 之後，每個人的本機電腦都會有自己的一份副本可以管理。

若成員 A 開始修改與編輯後，可再推送（push）到遠端儲存庫。

成員 B 由於當時 clone 時，還沒有 A 的修改，所以可能會發生同一個檔案上的衝突（conflict）。

此時 B 要跟 A 溝通，把差異合併（merge），或是重置基準（rebase）。

以 AdGuardHome 開源軟體為例，可以看到開發者針對每個新版本會開新的分支（branch）管理，程式碼由多個不同使用者提交。

其中在提交程式碼並修復新的 bug 可能會開新的分支，最終由主開發人員評估後 merge。

什麼是遠端儲存庫？

在本地端初始化一個新的 repo 後，可以將本地端的內容 push 到遠端儲存庫。

遠端儲存庫的主要功能是儲存程式碼，是位於網路上的伺服器。

另外可能還有這些功能：

  1. 程式碼審查（code review）
  2. 問題追蹤（issue tracking）
  3. 持續整合（continuous integration，CI）
  4. 持續交付（continuous delivery，CD）
  5. 建立 wiki 說明頁面
  6. 專案管理
  7. 權限管理
  8. 視覺化進度（visualize progress）
  9. 等...

目前主流的遠端儲存庫主要有：

  • GitHub（微軟）：

    1. 有程式碼審查、問題追蹤、持續整合等功能。
    2. 在個人開發者和企業中都廣受歡迎。
    3. 分成免費和付費方案，可以依需求選擇。

  • GitLab：

    1. 可以在公司內部架設，也有雲端服務可用。
    2. 強調 DevOps 和 CI/CD 整合，是完整的 DevOps 平台。
    3. 分成社區版（免費）和企業版（付費）。

  • Azure DevOps（微軟）：

    1. 不僅是程式碼管理工具，還是一個完整的 DevOps 平台，包括程式碼管理、CI/CD、專案管理等功能。
    2. 深度整合了 Azure 雲端服務。
    3. 有免費和付費計畫，企業和團隊可以挑適合的方案。

上述平台，會根據使用人數、是否付費，提供不同層級的服務。

在個人開發者中，使用最多的遠端儲存庫就是 GitHub 了。

中大型企業往往不想將程式碼放到 GitHub，會考慮自己架設 GitLab 放在公司內部的伺服器上。

而某些外國企業在合作上，甚至需要跑 DevOps 追蹤程式碼，會另外要求用 Azure DevOps 做程式碼管理與敏捷開發。

開始使用 Git

選擇指令介面還是圖形介面？

開始使用 Git 前，首先要有好的 IDE。

傳統上的 IDE 就是 cmd + vim/nano 等文字編輯器，在命令提示字元裡一行一行輸入指令。

git merge 時遇到檔案衝突，必須在指令模式下找到衝突的程式碼、編輯、存檔、git add 後，最終沒衝突再 git commit。

相比之下，圖形介面（GUI）把這些複雜的指令輸入簡化掉，用點選的就能解決許多問題。

對我來說，大部分的操作都用 GUI，畫面上看得清楚，操作也單純。不過有些特定的操作、或是制式化的操作，用指令模式處理會更快。

我建議熟悉兩種操作方式，就可以更靈活地使用 Git。

所以電腦請先安裝好：

  1. Git
  2. VS Code
  3. Windows Terminal（選用）
  4. PowerShell（選用）
  5. Clink（選用）

詳細的安裝方式可以參考 2026 Windows 必備軟體推薦：打造極致效率的 Awesome Windows 生產力與開發工具總覽。

我最初開始學 Git 時，使用的遠端儲存庫為 GitHub。

GitHub 提供了 GitHub Desktop，這套軟體少了蠻多重要的功能，因此不建議使用。

還有像是 SourceTree、TortoiseGit 等其他 GUI，雖然是 Git 官方所推薦，但相較於 VS Code 的擴充性還是差了一大截所以也不推薦。

註冊 GitHub

到 GitHub 註冊，取得一個免費放程式碼的空間。

  • 無限制的公共/私人儲存庫
  • 自動安全和版本更新
  • 每月 2,000 分鐘的 CI/CD
  • 公共儲存庫免費
  • 500 MB 的套件儲存
  • 公共儲存庫免費
  • 問題和專案
  • 社區支援 GitHub Copilot 存取

無論是架設技術部落格或是存放個人的程式碼都綽綽有餘。

至於註冊方法照著官方的說明一步一步做就好，不會很困難。

使用 Git 的迷思

  1. 害怕使用 Git

    萬物皆可 Git，只要檔案不要超過 100 MB（經驗法則）。除了程式碼外，也可以用來追蹤像是 .md 或是圖片檔案。

  2. Git 太複雜，難以入門

    在網路上，常常會拿 Git 跟 SVN 比較，並聲稱 Git 很複雜。

    實際上，初次接觸 Git 時，你只需要記住基本操作: git commit，並在提交時附上簡單的說明。隨著時間的推移，你會逐漸熟悉其他操作，如合併（merge）或重整（rebase）分支等。

    如果擔心操作出錯，可以建立一個新的分支（例如 TEST）來操作。當你確定操作無誤後，可以刪除原始分支（如 main），並將測試分支（TEST）重新改名為主分支（main）。這樣可以減少犯錯的機會。如果 TEST 分支在 merge 卡住、出現問題時，直接刪掉就好。
