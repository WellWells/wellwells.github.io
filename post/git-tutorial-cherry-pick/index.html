Git 基礎教學：使用 VS Code 執行 Cherry Pick

在 VS Code 用 Git Cherry Pick 跨分支搬移特定提交：單筆與連續範圍的挑選指令，以及用 checkout 只取出某個檔案變更的做法。

什麼是挑選？

挑選（cherry-pick）是一種從一個分支中選擇特定提交並將其應用到另一個分支的方法。在兩個不同的開發者分別在 A 和 B 兩個分支上獨立開發的情況下，假設 A 分支上提交了一個重要的 Bug 修正。B 分支挑選該提交就能套用這個 Bug 修正。

相較於將 B 分支變基到 A 分支上的做法，挑選的目的是單純套用單一或數筆提交，而不是整個分支的合併或重整。

挑選現有提交

使用 VS Code

挑選是 Git 中相對簡單的部分。在目前分支上對著想要的提交右鍵，選擇 Cherry Pick... 即可。

使用指令

目前的分支狀態，注意提交 ID 的部分：

目前在 CP 分支上的提交是 52a310a7，如果只想挑選 2f01e37，在指令中輸入git cherry-pick 2f01e37：

git cherry-pick 頭^..尾

挑選特定檔案的變更

在 Git 中，cherry-pick 命令僅能挑選整個提交，而無法直接挑選某個特定檔案的變更。但如果只想挑出某個提交或分支中的特定檔案，可以使用 checkout 命令來達成這個目標。

1
2
3
4

# checkout 某分支下的某個檔案
git checkout BRANCH_NAME FILE_PATH
# 或是 checkout 某筆提交底下的某個檔案
git checkout COMMIT_SHA FILE_PATH

如下圖所示，目前所在的 CP 分支位於提交 ID 52a310a7，可以用 checkout 命令取得提交 ID 為 d616aa83 (WITH_ANOTHER_FIX_ALL) 這筆提交底下的 file.txt：

1
2
3

git checkout d616 file.txt

此時檔案會放進暫存區，接著在 VS Code 提交：

最終的分支結果如下圖所示，其中提交 ID 為 223cf241 的 File.txt_已修復 包含了「修正 file.txt」與「WITH_ANOTHER_FIX_ALL」的變更。這是簡化和合併提交時常見的技巧，把不同提交的變更集中到同一個檔案，程式碼庫的改動會更好管理。

總結

使用挑選指令，可以把其他分支的提交複製到目前分支。隨著挑選次數增加，分支結構會變得越來越複雜且難以維護。

適時利用變基或合併操作可以簡化分支的複雜度。尤其像最後那個案例，一筆提交裡包含多個檔案的修改，合併時更容易遇到檔案衝突，對專案還不熟的新手來說很難處理。
