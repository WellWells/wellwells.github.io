引言

Secure Shell（SSH）是一個安全協定，允許兩台電腦在加密的連線上交換資料（執行命令、傳檔案），保證資料的安全與完整性。

SSH 通常用於兩台電腦的遠端登入。它取代了舊的遠端存取協定，像是 Telnet 是以明文沒有加密的方式傳輸密碼和內容。而 PTT 也在 2020 年關閉不安全的 Telnet 協定，改用 SSH 或是 WebSocket 協定，讓通訊過程都有加密，防止竊聽與竄改。

SSH 除了裝置遠端連線，還可以：

  • 建立 SSH 隧道（Tunneling）做連接埠轉發，安全地存取網路資源。
  • SFTP、SCP 可以安全地上傳或下載檔案。
  • rsync 用於檔案同步，減少傳輸用量。
  • 其他應用...

Linux、macOS 或是 Windows 預設都整合了 OpenSSH 套件。OpenSSH 是一套開源的 SSH 實作，裡面包含了：

  • 遠端操作工具

    • ssh，用於遠端登入到其他主機並執行命令。
    • scp，本地與遠端的檔案傳輸。
    • sftp，類似 FTP 的使用方式，但傳輸都有加密。

  • 金鑰管理工具

    • ssh-add，將私鑰加入 SSH 代理程式，之後不必再輸入密碼就能用私鑰驗證身分。
    • ssh-keysign，用於簽署 SSH 憑證，供身分驗證使用。
    • ssh-keyscan，用於掃描遠端主機以搜尋其 SSH 公鑰。
    • ssh-keygen，用於產生 SSH 金鑰對（公鑰和私鑰）。

  • 伺服器端

    • sshd (SSH Daemon)，在伺服器上執行的常駐程式，負責接受來自用戶端的 SSH 連線請求。
    • sftp-server，處理 sftp 用戶端的請求與檔案傳輸。
    • ssh-agent，管理使用者的 SSH 金鑰，並在需要時拿這些金鑰驗證身分。

本文章重點會著重在如何建立公鑰與私鑰，並用這兩把鑰匙做到免密碼認證。另外也會提及伺服器端如何執行 SSH 服務，並讓使用者端用 SSH 連上來。

傳統的密碼登入方式，是輸入正確的使用者密碼來驗證身分。若伺服器暴露在公共網路上，可能會面臨暴力攻擊的風險，導致伺服器資料外洩。

為了提升安全性(與懶得輸入密碼?)，可以改用公私鑰驗證。如此一來不需要輸入密碼就可以連線，且駭客在沒有私鑰的情況下也無法登入。

💡 本文章有使用 Tailscale 建立內網，讓本地端與伺服器端的電腦可以用 hostname 或是 IP 位址連線。

兩台電腦要連線需要有 IP 位址，如果是公網 IP 位址則需要在路由器設定連接埠轉發到內網，但相對暴露 SSH 連接埠危險的。 不想暴露連接埠、沒有公網 IP 位址或是無法修改路由器設定等，可閱讀《使用 Tailscale 輕鬆建立安全且私密的隧道》，讓兩台電腦連上線。

SSH 重點摘要

  1. SSH 主要兩種驗證方式為：

    • 密碼身分認證（Password-based authentication）
    • 公鑰認證（Public-key authentication）

  2. 設定好 SSH 金鑰後，登入方式可使用金鑰登入，不需要輸入密碼。

  3. 公開金鑰 內容會填寫在 遠端伺服器 上的 authorized_keys。

  4. 私密金鑰 會保留在你的本機系統上，保護此私密金鑰，不要共用它。

  5. 公開金鑰可以與任何人共用，私密金鑰只有自己有存取權限。

  6. SSH 可以選擇不同加密演算法。RSA 為預設，也是目前廣泛且相容性最好的加密方法；Ed25519 效能比 RSA 好但相容性較差，目前絕大多數伺服器都逐漸支援，是我個人產金鑰的首選。挑哪一種，只要本地端與伺服器可以正常通訊即可。

  7. 絕大多數存取 GIT 的傳輸協定是 SSH。意味著在遠端操作像是 clone, push, pull 都會要求認證。

SSH 加密方式，雖然 RSA 比 Ed25519 相容性好，但實際在使用上建議以產生 Ed25519 為優先以確保安全性與速度。

SSH 金鑰建立與連線流程

假設 nodeA 為本地端（使用者），nodeB 為伺服器端。

nodeA 為工作的電腦，像是要 git clone，或是 SSH 連線到別的電腦上。

nodeB 為被連線的電腦，像是 git 伺服器，網頁伺服器、代理伺服器、虛擬專用伺服器等...

  1. 在 nodeA 或 nodeB 產生金鑰（公鑰與私鑰）。
  2. 把私鑰放在 nodeA，公鑰放在 nodeB。
  3. nodeB 建立 ~/.ssh/authorized_keys，並填入公鑰。
  4. nodeA 建立 ~/.ssh/config，填入連線資訊，連線資訊包含伺服器 IP 位址與私鑰路徑。
  5. nodeA 之後 SSH 連線時，預設就會使用金鑰。

💡要特別注意的是：

  1. 確定私鑰只有自己有存取權限，且 nodeB 沒有私鑰。
  2. nodeB 如果是 Windows 且為系統管理員。路徑需改為： C:\ProgramData\ssh\administrators_authorized_keys
  3. 如果連線失敗或設定金鑰後卻仍要求輸入密碼，可以在 SSH 連線時加上 -vvvv 除錯。

建立金鑰

由上述的 SSH 連線行為，可以發現目前尚未設定金鑰，所以預設還是用密碼登入。

建立金鑰很簡單，在用戶端或伺服器端執行都可以。

Windows 與 Linux 產生金鑰的指令都是 ssh-keygen。

其中參數的部分：

  • -t ed25519 為產生一對 ed25519 金鑰。或將其改為-t rsa -b 4096，表示使用 RSA，長度為 4096 位元。
  • -C "xxx" 裡面的參數為任意值，主要是加入備註，幫助辨識金鑰是由誰建立的。
1

ssh-keygen -t ed25519 -C "your_email@example.com"

產金鑰的過程，會看到 Enter file in which to save the key 的路徑，預設是在個人目錄底下的 .ssh 資料夾底下。

決定好路徑後，會再詢問 passphrase（金鑰密碼）。若為空值，未來使用金鑰驗證時不需要密碼；若設了 passphrase，駭客就算取得私鑰，還有第二道牆需要突破。

金鑰是儲存在個人電腦、個人帳戶，一般來說外洩的機會有難度。若害怕金鑰外洩的，可以輸入非空的數值。如此未來使用金鑰驗證時，還會額外要求輸入密碼。但相對又麻煩了...

passphrase 可以用 ssh-agent 快取，在快取時間內不用重打 passphrase。

此部分建議設定金鑰密碼以提高安全性，並搭配 金鑰密碼搭配 ssh-agent 做快取。

使用 SSH 金鑰建立兩台電腦連線

接著把公鑰（nodeA_ed25519.pub）複製到伺服器上，可以用 scp 這個程式。

用法為：scp 本地檔案路徑 使用者名稱@伺服器:伺服器路徑

Windows 複製公鑰到 Windows

1

scp C:\Users\wells_nodeA\.ssh\nodeA_ed25519.pub wells@nodeB:C:\Users\wells_nodeB\.ssh\nodeA_ed25519.pub

Windows 複製到 Linux

1

scp C:\Users\wells_nodeA\.ssh\nodeA_ed25519.pub wells@nodeB:~/.ssh/nodeA_ed25519.pub

輸入完密碼後，scp 就會把公鑰複製到伺服器上。

複製後，在 nodeB 上（伺服器端），新增檔案並填入公鑰內容。

使用者為根據 nodeB 的使用者

  • Windows 一般使用者：C:\Users\wells_nodeA\.ssh\authorized_keys
  • ⚠️ Windows 系統使用者：C:\ProgramData\ssh\administrators_authorized_keys
  • Linux 一般使用者/root：~/.ssh/authorized_keys
  1. 記事本開啟公鑰 (nodeA_ed25519.pub)
  2. 全選複製內容
  3. 新增上述檔案
  4. 在上述檔案內，貼上公鑰內容後存檔

最後，本地端 nodeA 新增 config 設定檔後儲存：

  • Windows：C:\Users\wells_nodeA\.ssh\config
  • Linux：~/.ssh/config
1
2
3
4

Host nodeB_wells
    User wells
    HostName nodeB
    IdentityFile ~/.ssh/nodeA_ed25519

設定檔內容說明

  • Host 為個人可辨識的名稱
  • User 是伺服器上的使用者名稱
  • HostName 為伺服器的 IP 位址或 host 名稱
  • IdentityFile 為私鑰路徑，Windows 與 Linux 上都可以使用 ~/ 表示個人目錄

儲存後，就可以用金鑰登入，若登入失敗要求輸入密碼，可以檢查

  • 金鑰是否正確
  • authorized_keys 路徑是否正確

使用 SSH 金鑰存取位於 Synology 上的 Git 伺服器

在本地端 Windows/Linux 上建立好金鑰後，將公鑰放置 Synology 的個人使用者目錄下的 .ssh 資料夾，沒有目錄的話需要自行建立。並新增 authorized_keys 並填入公鑰內容。

在本地端上的 config 設定檔，填入主機資訊：

  • Windows：C:\Users\wells\.ssh\config
  • Linux：~\.ssh\config
1
2
3
4

Host NAS
    User wells
    HostName 192.168.50.12
    IdentityFile ~/.ssh/nodeA_ed25519

設定檔內容說明

  • Host 為辨識名稱
  • User 為 NAS 登入帳號
  • HostName 為 NAS IP 位址
  • IdentityFile 為私鑰路徑

執行 git remote 相關指令時，會優先使用金鑰認證，不用輸入密碼。

進階安全設定

此章節適用於對安全性敏感的使用者，也建議設定以下相關 config 以達到更高的安全性。

關閉密碼認證

如果預設遠端伺服器 (nodeB) 走的是密碼認證，確定金鑰可以成功登入後，可以關閉密碼認證提高安全性。

設定檔路徑：

  • Windows：C:\ProgramData\ssh\sshd_config
  • Linux：/etc/ssh/sshd_config

找到約 50 行附近，並將 PasswordAuthentication 改為 no，記得移除前面的 #

1
2

---#PasswordAuthentication yes
+++PasswordAuthentication no

修改後，重新啟動 sshd 後，下次登入僅使用金鑰進行，若金鑰遺失則無法登入

用 PowerShell 重新啟動 sshd

1

Restart-Service sshd

Linux 重新啟動 sshd

1

sudo service ssh restart

金鑰密碼搭配 ssh-agent

在建立金鑰章節有說明 passphrase 預設可為空值，SSH 時不需要密碼。但私鑰如果外洩，駭客可以直接拿這把私鑰連線。

所以建立金鑰時可以加入 passphrase，並用 ssh-agent 把私鑰快取在記憶體中，只要輸入一次密碼，之後都會用這份快取驗證金鑰。

以下操作使用 Windows 為範例，Linux 的操作基本相同。

其主要差異在 Windows 底下 SSH 執行檔分為兩包，分別為：

  1. OpenSSH 底下的 C:\Windows\System32\OpenSSH
  2. Git 目錄底下的 C:\Program Files\Git\usr\bin

故需要將 Git 的 sshCommand 更改為 OpenSSH 的路徑。

Windows：

 1
 2
 3
 4

 9

# 更改 git 的 ssh.exe 為 OpenSSH 底下的路徑，若未更改，則無法使用儲存在 OpenSSH 記憶體的私鑰
git config --global core.sshCommand C:/Windows/System32/OpenSSH/ssh.exe

# 開機自動執行 ssh-agent
Get-Service ssh-agent | Set-Service -StartupType Automatic

# 啟動 ssh-agent
Start-Service ssh-agent

# 檢查 ssh-agent 的狀態
Get-Service ssh-agent

# 使用 ssh-add 把私鑰加入 ssh-agent，此時會要求輸入 passphrase
ssh-add C:\Users\wells\.ssh\nodeA_ed25519

# 列出目前 ssh-agent 中已載入的金鑰
ssh-add -l

# 刪除所有金鑰
# ssh-add -D

Linux：

# 若預設為 bash，則在 ~/.bashrc 末端加入以下行
eval "$(ssh-agent -s)"

# 新增私鑰到 ssh-agent，並輸入 passphrase
ssh-add ~/.ssh/nodeA_ed25519

macOS 指令可能有些不同，請參閱解法

確定 ssh-agent 已載入私鑰，私鑰可以備份至安全的地方，並在此電腦上移除。

只要 ssh-agent 有成功啟動，預設都會由 agent 做金鑰認證。

最終，本地端 nodeA 的 .ssh 資料夾，應該只有 known_hosts 與 config。

config 裡面的 IdentityFile 路徑也可以移除。

1
2
3

Host nodeB_wells
    User wells
    HostName nodeB

ssh-agent 預設時間是永久，若要提高安全性可以設定快取時間。

1

ssh-agent -t 1h

使用 SSH agent 轉發

GitHub 與 nodeB 上已經填入公鑰，本地端 nodeA 也已經用 ssh-add 把私鑰加進 ssh-agent。

所以本地端可以 SSH 到 nodeB，或用 git 相關指令把 GitHub 的程式碼 clone 到 nodeA。

現在，若要在 nodeB 上 git clone 把 GitHub 的程式碼抓下來，私鑰不需要放到 nodeB。

這時可以用 SSH agent 轉發。

1
2

# 加入 -A 可以啟用 SSH 代理轉發。允許在遠端伺服器上使用本地的 SSH 金鑰。
ssh -A wells@nodeB

如果每次 SSH 都要帶參數覺得麻煩，也可以在 config 內新增 ForwardAgent

1
2
3
4

Host nodeB_wells
    User wells
    HostName nodeB
    ForwardAgent yes

連線後，遠端伺服器可以使用 ssh-add -l 檢查是否已經載入私鑰。

若已載入私鑰，就可以直接用該金鑰在 nodeB 上 git clone。

Windows 預設內建版本為 8.6p1，agent 轉發後檢查伺服器上的私鑰是有載入的。

但 git clone 會出現公鑰認證失敗，此部分為 OpenSSH Bug。

Windows 使用者可以到微軟 OpenSSH Release 手動安裝_8.9p1 後，git 相關操作就正常了。

另外，如果 NodeB 的信任度不高（例如上面有其他使用者擁有 root 權限），可考慮改用 Proxyjump 當跳板。原理是私鑰只留在 NodeA 上，當要在 NodeB 存取 GitHub 時，把 NodeA 設為跳板。

好處是不用從 NodeA 把金鑰轉發到 NodeB，而是直接在 NodeA 上做 SSH 操作，再把結果回傳到 NodeB。
