使用 Tailscale 輕鬆建立安全且私密的隧道

用 Tailscale 在電腦、手機、NAS 之間建立安全的私人網路，不用碰路由器設定或連接埠轉發。這篇一步步帶你註冊、安裝、連線，並說明直連與中繼、NAT 穿透與裝置命名。

引言

當人在外時，如何遠端連線到家裡的電腦、工作電腦、或是家中的 NAS？

本篇文章會一步一步教你怎麼用 Tailscale 連上內網裝置。

寫給對電腦不清楚的人

要讓裝置能夠互通，首先每台裝置都要能連上網路，再由 Tailscale 把它們串起來。

首先在官方網站註冊，並於電腦 A、電腦 B、手機、NAS 或其他待連網裝置，安裝 Tailscale 並登入帳號。

登入帳號後，等同於登入 tailnet。這些裝置會取得彼此的內網 tailnet IP 位址。

之後就能直接用裝置名稱連線，像是遠端桌面連線、列印、存取 NAS 等...

不想知道 VPN 背景的可直接跳到如何安裝 Tailscale、裝置重新命名與結論。

如何遠端存取裝置？

在標準的情境應用中，例如：

  1. 自己架設的網頁伺服器（localhost:80）
  2. NAS 本身提供 Web GUI（localhost:5000）
  3. Windows 遠端桌面連線（localhost:3389）
  4. DNS 伺服器（localhost:53）
  5. 其他服務...

如果想讓外網的人存取這台伺服器，首先要有個對外 IP (WAN IP) 位址（IP 位址查詢）。從外部就能靠這個對外 IP 位址連進來。

連線後會找到路由器（router），設定此路由器把對外的 port 導到對應的應用。

以 OpenWRT 的路由器介面為例，以下是路由器的設定，會在外網 IP 位址連線時做連接埠轉發（Port Forwarding）到區網 IP (LAN IP) 位址：

其目的在於把 外網 IP 位址:Port 導向至 內網 IP 位址:Port。

以上圖為例，就是把外網進來的連線，分別導到內網的 DNS（192.168.1.2）、網頁（192.168.1.3）與遠端桌面（192.168.6.4，外網 Port 82 → 內網 Port 3389）這幾台伺服器。

設定好連接埠轉發後，便可由外部存取 DNS、網頁或是遠端桌面了。但上述連接埠轉發的方式，是讓外網 IP 位址直接存取內網的相關資源，也意味著任何人都能連線。如果想要讓特定使用者存取，則必須自己建立虛擬私人網路（virtual private network，VPN）。

建立虛擬私人網路（VPN）

VPN 是一種服務，它會開一條安全的加密通道，把使用者連到遠端伺服器。這樣可以隱藏使用者的真實 IP 位址並加密資料傳輸。

以 Windows 為例，根據微軟官網教學於 A 電腦上建立 IKEv2、L2TP 或是 IPsec 協定的 VPN 後，在另外一台 B 電腦就可以嘗試連線了。

連線成功後，B 電腦便跟 A 電腦一樣，可以存取 NAS 服務、印表機等內網資源。

要注意路由器與電腦的防火牆是否擋掉了 UDP Port 500、1701、4500，一旦被擋，VPN 就會連不上。

常見的 VPN 協定

  1. OpenVPN：開源專案，提供多種驗證方式（金鑰、憑證、帳號密碼），可跨裝置使用，整體上安全、易用、相容性也好。

  2. WireGuard：於 2020 年整合於 Linux，較為新興的 VPN 協定。其特點為使用 UDP 傳輸、比 IPsec 與 OpenVPN 更快、效能更好，並支援跨平台。較新的路由器有些會整合 WireGuard 伺服器。

  3. L2TP/IPsec：專有協定（Cisco & Microsoft），已經內建於系統中，不需要安裝軟體就可以架設與連線。

  4. PPTP：已淘汰的點對點協定。

什麼是 Tailscale？

Tailscale 是一個基於 WireGuard 協定的 VPN 軟體，可以把多個裝置連起來，組成一個虛擬內部網路。

傳統上設定 WireGuard 較為繁瑣，無論是在架設、或是維護上都有一定困難。例如在各個裝置先透過 wg-quick 產生公鑰與私鑰，然後在該裝置上安裝 WireGuard 後，設定相關的檔案，檔案內容需要填寫監聽的埠、專用 IP 位址、私鑰與對等公鑰。

例如一台伺服器（Server）與兩台用戶端（Client），公私鑰設定如下：

裝置私鑰公鑰設定
伺服器AB填入自己的私鑰 A、用戶端的公鑰 D、公鑰 F
用戶端 1CD填入自己的私鑰 C、伺服器的公鑰 B
用戶端 2EF填入自己的私鑰 E、伺服器的公鑰 B

若往後有更多用戶端、伺服器需要重新設定，且以上情況僅為 1 個伺服器的例子，多個伺服器設定起來會更加複雜。

Tailscale 幾乎不用手動產生金鑰、寫設定檔就能架起私人 VPN，還附一個完整的 Web GUI 顯示已連線的裝置。

Tailscale 基於 WireGuard，但有以下特點：

  1. 不使用軸輻式網路（hub-and-spoke network），而是使用網狀網路（mesh network），改善裝置之間的通訊。當然這也是 WireGuard 相較於其他 VPN 協定的不同之處。
  2. 支援 NAT 打洞（NAT hole punching）[*]，允許位於不同 NAT 後網路的兩個節點直接通訊，不需要中央伺服器，做到 P2P 直連。
  3. 若 NAT 打洞失敗，會退回中繼模式（relay server mode），改用 DERP（designated encrypted relay for packets）伺服器來建立連線。
  4. 連入 Tailscale 時，會使用協調伺服器（coordination server）交換使用者的資訊，如 IP 位址、Port、裝置狀態。
  5. 簡易的 Web GUI 管理介面，可以管理各個裝置彼此間的存取程度。
  6. 提供 MagicDNS、Taildrop、Tailscale Funnel 等功能，可以更方便的存取裝置。[**]

* 網路位址轉換（network address translation，NAT）是把 IP 封包標頭中的 IP 位址轉換為另一個 IP 位址，達成位址重用，讓內網所有裝置都可以使用同一個對外 IP 位址連接到外部網路。

** MagicDNS 讓你用裝置名稱存取裝置，不用記住 IP 位址。Taildrop 做的是類似 AirDrop 的功能，可以直接對其他裝置傳送檔案。Tailscale Funnel 則是反向代理，可以讓外網存取指定內網裝置。

Tailscale 的競爭對手

異地建立網路的相似產品有：

  1. ZeroTier
  2. Cloudflare Tunnel
  3. Netmaker
  4. Ngrok
  5. Twingate
  6. 等...

我有使用過的是 ZeroTier，使用的是自己的協定而非 WireGuard。個人使用心得是裝置連線 ZeroTier 私人網路後，會有一組內網 IP 位址，這組內網 IP 位址由於沒有 DNS 去解析，所以要存取該裝置，必須直接輸入 IP 位址。雖然有 ZeroNSD，不過印象中還是得自己架設，於是就轉用 Tailscale 了。

如何安裝 Tailscale

首先到官網註冊帳號，用的是 Google、Microsoft、GitHub、Apple 這四個身分識別提供者（identity provider），Tailscale 本身不提供註冊，也因此沒有密碼儲存在 Tailscale 上。

用這些帳號登入時，可以再開啟雙重驗證加強安全性，這樣基本上沒有人能直接存取你的私人網路。

登入後，由於沒有任何裝置，Tailscale 預設會列出下列不同的安裝方式，照著官方下載安裝即可。這邊雖然只列出 Synology 有提供官方安裝包，不過其他 NAS 也可以用 Docker 安裝。

下載並安裝後，電腦右下角會出現 Tailscale 的圖示，右鍵選擇 Log in... 會跳出登入介面。登入後，點選 Connect 即可加入私人網路（tailnet）。

重複步驟，iOS 或 Android 下載 Tailscale，登入後點選 Connect，裝置可能會要求加入 VPN，點選新增 VPN 後，也成功加入私人網路中。

可以於 Web GUI 中即時看到裝置的新增。

Linux 的部分也是一樣，只不過從 UI 介面改為命令列形式，根據官方 Linux 安裝教學，整體過程也是一致的。在登入過程中，系統會彈出一個網址，要求使用者在瀏覽器中輸入此網址登入。登入完成後，終端機將顯示 Success。

至此，安裝 Tailscale 並讓裝置能夠互相連線也就完成了。此時可以於 cmd 中，輸入 tailscale status 或是 tailscale ping IP_ADDRESS 來查看連線的狀態。

如果是 active; direct 表示走的是直連，ping 通常在 10–15 ms；反之，如果是 active; relay "xxx" 表示走的是中繼伺服器，延遲約為 80–300 ms。

會走中繼伺服器通常是因為防火牆擋掉了 UDP 連接埠，讓 Tailscale 只能退而求其次。但比起完全連不上，至少還有這條路可以走。

若要改善 ping 延遲，可檢查路由器相關設定或防火牆來達成直連：

  1. 例如開啟 UPnP 與 NAT-PMP（較不安全，但會自動設定好、省事）。
  2. 調整防火牆規則：關閉 UPnP，並允許內部裝置使用 UDP 通訊，開放本機埠 41641（目標埠依各廠商設定而定）。詳見 修改防火牆設定。
  3. 在 Linux 系統中，若連接埠被阻擋，請開啟終端機並執行：sudo ufw allow 41641/udp。

裝置重新命名

Tailnet 內建 DNS 功能，此功能可以把 hostname 或是裝置名稱轉為 IP 位址（當然你是 IP 位址愛好者的話記 IP 位址也是可以的🙃）。

對著右下角的圖示按右鍵，進入 Admin console。

裝置名稱預設是使用 hostname，若想要自訂裝置名稱，可以點選裝置右邊的 ... 的按鈕，並重新命名裝置。

後續便可以直接用裝置名稱連線。

Tailscale 相關指令（CLI）

Tailscale CLI 可以在 Linux 環境下開啟或關閉相關設定，在 Windows 上有圖示可以點選，也因此大部分的指令用不到（部分進階功能例外，要用 CLI 設定），不過用來檢查連線狀態很方便。以下用一張表格說明我自己常用的指令，更多詳細的說明可以參照官網。

Commands說明
tailscale status檢查目前網路狀態，可以檢查是否透過中繼還是直連
tailscale ping [IP 位址/device]檢查該裝置是否直連，若看到 DERP 表示走的是中繼
tailscale up [flags]連線至 tailnet，可以帶有不同的 flags
tailscale netcheck檢查目前 DERP 的狀態
tailscale update更新本裝置 tailscale 的版本

自己常用的就幾個，比較進階的可能等未來用到再說吧。

以下是我使用過的 tailscale up 設定：

  • --advertise-exit-node：假設 A 電腦有開啟這個 flag，那麼 B 電腦的流量可以使用 A 電腦作為出口，此時 B 電腦上網的 IP 位址就變為 A 電腦的 IP 位址。
  • --advertise-routes=<ip>：公開指定的子網路。例如，若 A 電腦的內網 IP 位址為 192.168.1.50，B 電腦可透過此設定直接存取 192.168.1.xx 子網路。

2025/5/18：已撰寫進階文章詳解相關設定，請參考《Tailscale 進階應用教學：Taildrop、出口節點與子網路路由設定》了解詳細配置。

結論

Tailscale 的安裝其實很簡單，防火牆、NAT 穿透這些麻煩事它都幫你處理好了。註冊完後，每個裝置裝上 Tailscale、登入同一個帳號就能加入 tailnet，彼此互連。每個裝置都有主機名稱，要改名或查看各個裝置的狀態，都在 Admin console 裡完成。

已加入 tailnet 的裝置還可以設定成子網路路由器，把整個網段廣播到 tailnet 裡，也可以把單一裝置節點分享（Sharing nodes）給其他帳號串聯網路，做出更複雜的網路應用。這些更進階的設定，官方網站有更完整的原理與資料。
