為什麼要申請自己的 LLM API 金鑰

將 AI 導入自動化流程時，OpenClaw、n8n 這類主流工具的第一步都一樣：先申請一組大型語言模型（large language model，LLM）的 API 金鑰，再填進工具的設定裡。

金鑰的作用是身分識別，供伺服器判定扣抵配額的帳號與專案。限制包含三項：每分鐘請求數、每日請求數與每分鐘 Token 數。呼叫時可指定特定模型版本以防被無預警更換，且每次回應皆附帶用量與錯誤碼，便於確認觸發的限制條件；網頁介面則無法取得此類資訊。

Yobi 的做法是用內建的瀏覽器視窗操作各家 AI 的網頁介面，不用金鑰也不用綁卡，多數情況下這樣就夠。有兩種狀況會失效：對方網頁改版後版面對不上，流程隨即中斷；網頁介面得等整頁渲染完才讀得到回應，排程一密就跟不上。這兩種狀況改用自備金鑰就能解決。

本文將實作 Gemini 與 OpenRouter 的免費金鑰申請、查詢配額並整合至 Yobi。透過「金鑰群組」輪詢，即可實現每日數百次的免付費呼叫。同一組金鑰用在 OpenClaw 或 n8n 的方式相同，後面會說明要填的欄位。

一組金鑰能拿來做什麼

OpenClaw、n8n 這類工具只要把金鑰填進憑證欄位就能使用；自己寫的程式也能直接呼叫模型，在命令列用 curl 測試，在 Python 裡改用 requests 或官方 SDK。官方 SDK 更省事：裝好 pip install google-genai，把金鑰存進環境變數 GEMINI_API_KEY，五行程式就能拿到模型的回應：

存成 hello.py，終端機下 GEMINI_API_KEY=剛剛申請的那串 python hello.py，幾秒內就會印出模型的回覆。

我長期用 Yobi 做的就是摘要，每十分鐘檢查一次 RSS，有新文章就濃縮成幾行推到手機。我在用 Telegram Bot 自動收 RSS 摘要寫過這條流程，那邊用的是不用金鑰的網頁模式，改成自備金鑰只需在模型選單換一個選項。

能不能免費做到這些，取決於金鑰是向誰申請的。

哪家發的 API 金鑰是真的免費

發 API 金鑰的服務很多，但有沒有免費層差別很大。對 OpenAI 和 Anthropic 來說，API 和自家網頁版、訂閱一樣是收入來源，企業把模型接進內部系統、第三方服務把 AI 包進自己的產品，都得付費呼叫 API。這兩家的官方定價頁上沒有免費方案，Anthropic 只提到新帳號會給一小筆試用餘額。Google 相反，Gemini 有常態免費層，額度就列在 AI Studio 的 Rate Limit 頁上，後面會實際查一次。

其餘各家都是同一套：綁信用卡後用多少付多少，或先儲值再扣。計價單位是每一百萬 token，輸入和輸出分開算，輸出通常比輸入貴三到五倍。各家後台都能設金額上限，開始呼叫之前先設好。

官方定價，2026 年 9 月，單位 USD／每百萬 token。市面上的模型有幾百個，我只留跑得動 agent 的那幾個，外加 Gemini Flash Lite：

本文說的「免費」只有一種定義：註冊帳號就能直接呼叫，不用綁卡、不用先儲值。符合的有三家，可用的模型都點得出名字。

Gemini 的免費額度集中在 Flash 系列，Pro 系列是 0，完全無法呼叫。OpenRouter 開放的是 id 結尾為 :free 的那批模型，輸入輸出都是 USD 0，整個帳號共用一個每日上限；用量排行榜前十名裡就有兩個 (free) 版本。Groq 註冊完直接在 Console 開金鑰就能呼叫，同樣不必留付款資訊。

Z.ai 的定價表上也有幾個標成 Free 的 Flash 模型，但文件沒寫註冊要不要綁卡，我沒有申請過，無法確認。Cerebras、SambaNova、Fireworks 給的是會過期的試用金，Cerebras 官方文件還寫要先加驗證過的付款方式，這種不算免費，只是延後付款。

申請 Gemini API 金鑰

到 Google AI Studio 用 Google 帳號登入，左邊選 API Keys，右上角按 Create API key。

幫金鑰取個好認的名字，專案選單留預設的 Default Gemini Project，按 Create key。

金鑰出現之後，這個視窗還會顯示專案名稱和專案編號。Google 現在發的金鑰開頭是 AQ.，不是以前的 AIza，看到不一樣不必懷疑拿錯。

金鑰的免費額度不在這個視窗裡，官方 Rate Limits 文件也已不提供總表，需自行至 AI Studio 查詢。左邊選 Rate Limit，右上角開啟 All models，每個模型的 RPM、TPM、RPD 就會全部列出，頁面上方也會標示目前所屬的 tier。

每分鐘請求數（requests per minute，RPM）是短時間的節流上限，每天請求數（requests per day，RPD）是一天的總量，每分鐘 token 數（tokens per minute，TPM）則取決於送進去的文字長度。呼叫只要超過其中任何一項，API 就會回傳 429。

額度算在專案上，不是算在單一金鑰上，同一個專案多申請幾組金鑰也不會變多。

申請 OpenRouter API 金鑰

OpenRouter 的賣點是單一金鑰：申請一組就能呼叫幾百個模型，換模型只要改 model id，不必再去各家開帳號，免費模型的支援也是它最完整。

到 openrouter.ai/settings/keys 登入，按右上角 New Key。取個名字，Expiration 留 No expiration，Credit limit 留空，按 Create。

金鑰只會出現這一次，視窗上明確寫著：You will not be able to see it again。關掉之後列表裡只看得到前後幾碼，忘記存就只能重新申請一組。

免費模型不用先儲值。 官方文件的限制表寫得很明確：:free 模型是每分鐘 20 次，累積儲值不到 USD 10 的帳號每天 50 次，滿 USD 10 之後每天 1,000 次。門檻在於是否儲值過，不是是否花完，那 USD 10 仍留在餘額裡，之後照樣能用在付費模型上。

自己查名單最準，開模型列表就只剩 :free 變體，篩選靠的是網址上的 variant=free，不是調整價格區間。上方分頁的 Text 標的數字就是當下的文字模型數量，我查的時候是 18 個，其中好幾個的 context 開到 100 萬 token。

這份名單更新得很勤，不少教學還在寫 Llama 3.3 和 Qwen3 Coder，現在列表上是 Nemotron、Ling、Inkling、Laguna 這些，照抄舊教學的模型 id 會直接收到錯誤。

三家都不用綁卡，差別在哪一道限制先觸發。Groq 的每天 1,000 次比 Gemini 多一倍，但每分鐘只給 8K token，送一篇長文進去就用掉大半，摘要類的流程很容易卡在這裡；Gemini 的 250K TPM 幾乎不必考慮長度。

要長期使用，Gemini 的 Flash Lite 最實在：每天 500 次、模型版本自己指定，長文也容得下。不夠用再付費，付費之後 Gemini 會從 Free tier 跳到 Tier 1，額度差好幾個數量級。

把金鑰接進 Yobi

Yobi 的自備金鑰（bring your own key，BYOK）在「設定 → 模型來源」最底下，按「新增實例」會展開一張表單。

「服務商」是下拉選單，主流服務商都已內建，選完 Base URL 會自動填上，不必自己翻文件。Gemini 填的是 https://generativelanguage.googleapis.com/v1beta/openai，OpenRouter 是 https://openrouter.ai/api/v1，付費金鑰或免費金鑰都能填。

清單裡沒有的服務商也能使用：捲到最底下選 OpenAI-compatible，自己填 Base URL 和模型 id，只要對方提供的是 OpenAI 相容端點就能呼叫。

表單由上往下填：

  1. 名稱：之後在模型選單看到的就是這個，寫清楚一點，例如 Gemini Flash Lite。
  2. 服務商：選 Gemini (Google)。
  3. API 金鑰：貼上剛剛拿到的那串。
  4. 模型：按旁邊的「載入模型」，Yobi 會從端點取回可用的模型清單，載完在欄位裡打字即可篩選，挑 models/gemini-3.5-flash-lite。我長期用的就是這個，一天 500 次足以應付大部分需求，速度也快。
  5. 按「測試」，出現「連線正常——模型已回覆」再按「儲存」。

OpenRouter 那組照同樣流程再來一次，服務商選 OpenRouter，模型挑結尾是 :free 的。

存好之後，聊天視窗右下角的模型選單最底下會多出一個「自備金鑰（BYOK）」分組，流程的 LLM 步驟也選得到。網頁模式仍然是預設，BYOK 只是多一個選項。

挑一個 BYOK 實例提問，回應直接從 API 回來，不會開瀏覽器視窗，標題底下還會標示這次用掉多少 token。

同一組金鑰接 n8n 與 OpenClaw

切換到別的工具，要填的還是同一組欄位：端點、模型 id、金鑰本身。n8n 和 OpenClaw 我只讀過官方文件，沒有實際接過，底下的欄位名稱照文件整理。

n8n 有現成的憑證類型，不必自己組 URL。Gemini 選 Google Gemini(PaLM) API，貼上金鑰，API Host 留預設的 https://generativelanguage.googleapis.com；官方文件有註明，這個 host 目前不支援換成自訂網址或 proxy。OpenRouter 則是獨立的 Chat Model 節點，接法跟 OpenAI 節點一樣，把 ai_languageModel 輸出接到 AI Agent 或 Basic LLM Chain 上。

OpenClaw 的做法是在 Control UI 開 Settings → Models 加金鑰，存進設定檔的 models.providers.<id>.apiKey，那一頁只標示金鑰來自設定檔還是環境變數，不會顯示金鑰本身。環境變數也能提供金鑰，Gemini 用 GOOGLE_API_KEY，OpenRouter 用 OPENROUTER_API_KEY，主模型寫在 agents.defaults.model.primary。

保管方式要留意：Yobi 把金鑰加密存在本機，設定檔式的工具很容易讓金鑰跟著專案進版控，一律用環境變數，不要寫死在流程檔裡。

Gemini 和 OpenRouter 都提供 OpenAI 相容端點，只要工具允許自訂 Base URL，沒有現成節點也能呼叫。Gemini 的相容端點就是前面 Yobi 自動填進去的那串 https://generativelanguage.googleapis.com/v1beta/openai。

用金鑰群組把額度疊起來

要把可用次數往上疊，必須跨不同服務商，或跨不同的專案和帳號。手邊本來就有工作和私人兩個 Google 帳號，或先前在不同專案下申請過好幾組金鑰的人，這一節剛好用得上。

Yobi 的「金鑰群組（輪詢）」就是做這件事。在「設定 → 模型來源」的 BYOK 區塊底下按「新增群組」，取個名字，把要輪流用的金鑰勾起來存檔。

上面那個叫 GeminiPod 的群組收了七組金鑰，存好之後會像一般實例一樣出現在模型選單裡，每次請求輪流換下一組，其中一組失敗就自動跳過。這些金鑰必須分屬不同專案或帳號，額度才會累加。

群組同時疊高兩種額度：每天的 RPD 和每分鐘的 RPM。對 agent 來說後者更關鍵，Gemini Flash Lite 只有 15 RPM，而 agent 一個任務裡工具呼叫來回好幾輪，短時間內就把每分鐘的額度用完。輪詢把請求分散到群組裡的每一組金鑰，同一段時間內能送出的請求跟著變多，某一組收到 429 也有下一組接手。

免費模型不是隨叫隨到

實測 OpenRouter 時連續遭遇三種錯誤，直到切換至第三個模型才成功呼叫：

  • nvidia/nemotron-3-ultra-550b-a55b:free 回 Upstream error from Nvidia: Service temporarily overloaded。免費的大模型排隊最久。
  • thinkingmachines/inkling:free 回 HTTP 403，訊息寫著這個模型只開放給官方名單上的 agentic app，名單外的工具無法呼叫。
  • google/gemma-4-31b-it:free 回 HTTP 429，當天的次數已用完。

同一時間 Gemini 那組第一次就通。要讓流程每天穩定執行，Gemini 的 Flash Lite 比 OpenRouter 的免費模型可靠得多；OpenRouter 的價值在於一組金鑰能換著試幾百個模型，那是另一回事。

結論

我長期使用的是 Gemini 3.5 Flash Lite，Yobi 的摘要流程用它就夠，OpenRouter 那組則加進金鑰群組當備胎。同一組金鑰移到 OpenClaw 或 n8n，填的還是那三個欄位，換工具不必重新申請。
