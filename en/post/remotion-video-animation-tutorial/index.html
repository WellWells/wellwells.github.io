Remotion Tutorial: React Video Animation, Written by AI

Adding a fourth title card means rebuilding the timeline in After Effects. In Remotion it's one more row of data. ProRes 4444 exports a transparent background, and Claude Code or Codex writes the animation. Example project included.

Introduction

The slowest part of making a tutorial video isn't the recording. It's the shots that come back every single time: the intro, the chapter cards, the little explainer that sits on top of a screen recording, the fake social post.

Build those in After Effects or Premiere and every one of them is hand-keyframed. The first version is fine. The problem starts on the second video, when three cards need to become four and the copy changes, and you're back in the timeline rearranging everything. Editing costs about as much as building it did.

Remotion takes a different route. The frame is described by a React component, and the animation is a function of "at frame n, where is this thing". Changing copy means editing a string in an array. Adding a card means adding a row of data. The timeline recalculates itself.

What do you need to know? Enough to type in a terminal. An AI agent wrote nearly all of the code here, and my goal turned into describing the shot I wanted clearly and then checking the result, so this never really went as deep as frontend development. That's why this post doesn't dump code at you: the complete example project is at the bottom for you to download, and what follows is about getting the project stood up, what the directories are for, and how to write the prompt.

This is a record of actually running it on an Ubuntu 24.04 box.

What this builds

A six-second, three-card animation. Cards spring in from the left, 0.8 seconds apart, each with a sound effect on entry, and the whole thing fades out at the end to leave room for a transition.

The same code also exports a transparent version you can drop straight onto a screen recording in your editor. The flow animation at the top of this post and the cover image both came out of the same project.

What Remotion is good at

Remotion's one real strength is same layout, different data. So these pay off:

  • Layouts that repeat. Intros, chapter cards, lower thirds, the subscribe card at the end. Build once, swap the text every video after that.
  • Data-driven charts. Bars, lines, leaderboards, with the numbers coming straight from a CSV or an API. Change the data and the frame recalculates instead of you nudging keyframes.
  • Bulk output. One row of data, one video. Year-in-review clips, report cards, personalized marketing videos are the same layout run a few hundred times.
  • Overlays for screen recordings. Export with a transparent background and lay it over the footage.
  • Things that were always drawn anyway. Line-by-line code highlighting, map routes, audio waveforms, captions. Dragging those with a mouse is miserable. Describing them in code is natural.

These are the ones to leave alone:

  • Motion design that needs feel. Shots where you keep nudging the easing curve and judge the timing by eye. The After Effects graph editor is much faster.
  • Cutting, grading, mixing. Remotion doesn't do any of it. It makes the material and you take that back to an editor.
  • Heavy 3D and VFX. It can host Three.js, but it isn't in the same league as real 3D software.

If you will make this video exactly once, and every move needs to be judged by eye, After Effects is quicker. If there will be a second and a third and the only difference is the data, Remotion starts paying for itself on the second one.

Local renders don't need a Remotion license key

Remotion uses the Remotion License, not an open-source license like MIT:

Who you areCost
IndividualFree, commercial use included
For-profit company of 3 or fewerFree
Non-profitFree (schools and government bodies don't count)
Company of 4 or moreCompany License required

The threshold counts everyone at the company, not just engineers, and part-timers and contractors count too.

A local render needs no license key, and you lose nothing by leaving it unset. Running npx remotion render reports nothing anywhere.

Whether you can use it for free comes down to the table above. It's a contract, not a technical lock. How you use it is your own decision.

Environment: Node.js

Remotion runs on Node.js, so Node comes first.

Linux

Install it through nvm. I covered this in Ubuntu Server 24.04: install, partitioning and network setup, so follow that.

The upside is that versions coexist and you can switch any time:

1
2
3

nvm install 24        # install Node 24, the current LTS
nvm use 24            # switch this terminal
nvm alias default 24  # use this version in new terminals

If you'd rather skip nvm, brew install fnm works on Linux too, which is the tool the Windows section below covers.

Windows

Windows gets fnm, short for Fast Node Manager. It's a Node version manager written in Rust, the commands are near-identical to nvm, it runs on macOS, Windows and Linux, and it reads .nvmrc and .node-version.

First, install it with winget:

1

winget install Schniz.fnm

Second, set up your shell so fnm takes over the node command. That goes in the PowerShell profile, which doesn't exist yet on a fresh install, so create it first. -Force creates the parent folder too:

1

if (-not (Test-Path $PROFILE)) { New-Item $PROFILE -Force }

Open it in an editor, Notepad or VS Code:

1
2
3

notepad $PROFILE
# or
code $PROFILE

Add this line at the bottom of the file:

1

fnm env --use-on-cd --shell powershell | Out-String | Invoke-Expression

Save and close. Reopen the terminal and install Node:

1
2
3

fnm install 24   # install Node 24
fnm use 24       # switch this terminal
fnm default 24   # make it the default

Check it took:

1
2

PS C:\Users\wells> node --version
v24.16.0

Creating the project

Pick a directory for the video project, make the folder and cd into it. An empty folder means the wizard installs right there instead of asking for a directory name:

1
2
3

mkdir video-demo
cd video-demo
npx create-video@latest

It asks four things:

QuestionPickWhy
Choose a template:BlankThere are 23 templates. Blank is the simplest; Hello World ships an animation you'd delete anyway
Add TailwindCSS?YesAdding it later means configuring the bundler yourself
Add agent skills?YesThe one question that matters most, covered below
Open in VS Code?YesOpens straight after install, saves a step

Run npm i yourself afterwards, the wizard doesn't install packages for you:

1
2

npm i
npm run dev

It won't open a browser for you. Go to localhost:3000.

What the project looks like

After install the tree looks roughly like this:

 1

10

video-demo/
├── src/
│   ├── Root.tsx          ← which videos this project contains
│   ├── Composition.tsx   ← the frame itself
│   └── index.ts
├── public/               ← images, audio, fonts go here
├── .agents/skills/       ← official skill docs, agents read these themselves
├── out/                  ← rendered videos land here
├── remotion.config.ts    ← export settings
└── package.json

This tree is worth understanding before any of the code, because only two places actually need your attention.

src/Root.tsx is the index. One project can hold many videos, and each one is called a composition. This file registers which videos exist, how long each is, what size and what frame rate. Changing copy, changing duration, adding an English version, all of it happens here.

The component itself is an ordinary React component: <div> elements and CSS. The only difference is useCurrentFrame(), which tells you the frame number, and you answer with where things should be.

Files under public/ can't be reached by a literal path in code. Use staticFile() so Remotion knows where to find them at render time.

The rest you install once and rarely touch.

Remotion Studio: save, and the frame follows

Three parts: the composition list on the left, which is what Root.tsx registered; the current frame in the middle; and the timeline below, where you can drag the playhead to any frame.

It's really a dev server. Save a file and it picks up the change, recompiles, and the preview updates without a restart or a re-render. The change-a-word, look-at-it loop is instant. That's where the feel departs most from After Effects: there you drag a timeline, here you edit data and look at the result.

No video file exists yet at this stage. The Studio just runs your component in a browser. A file only appears at the render step further down.

Letting Claude Code or Codex build the animation

Installing Remotion Agent Skills

That Add agent skills question from the wizard pulls down 12 official skill documents when you answer Yes. It affects output quality more than any prompting trick I've tried.

An empty project gives an AI nothing to go on: it doesn't know what this version's API looks like, which settings a transparent background needs, or which patterns flicker during a render. Remotion code written from training data alone is frequently the old API.

If you skipped it, add it inside the project:

1

npx remotion skills add

That creates .agents/skills/, holding Remotion's official skill docs, which Claude Code, Codex and Antigravity all read on their own. You install it once and configure nothing per tool.

What's inside is more than API reference. The maps skill, for example, lists five routes to animated maps and states the cost of each: Mapbox looks good and has 3D buildings but needs an API key; MapLibre is free and needs no key, at the cost of no 3D buildings. You wouldn't know that trade-off without digging through docs, and an AI certainly won't invent it.

Writing the prompt

A good prompt nails the spec down. The five colorful bars springing up in the video at the top of this post came from one sentence I gave an agent. Broken apart, it was six things:

ElementWhat I actually wroteWhat happens if you skip it
File locationput it in src/demos/SunnyBars.tsxIt may edit an existing file and change work you already had
Spec1920x1080, 90 framesIt picks a size and duration for you
Contentfive colorful bars springing up from the bottom, different heights, a dot on top of eachYou get something very generic
Feel of the motionuse spring for the bounce, then let the row drift gently once it landsYou usually get a fade, with no elasticity
Stylebright, warm colorsDefaults run blue and grey
Boundariesonly add this file, don't touch anything else, don't register a composition in Root.tsxIt will helpfully edit a lot you didn't ask about

The fourth one is the easiest to forget and makes the biggest difference. A bounce and a fade are completely different code, and without being told the agent picks the safest option.

Three more things:

  • Seconds beat adjectives. "Title fades in over the first second, then a card every 0.2 seconds" is far more precise than "make it snappier".
  • Name the library. Whether to use GSAP or Lottie is your call, not its.
  • Make it check itself. Ending the prompt with "run npx tsc --noEmit when you're done and fix any type errors" saves a round trip.

You don't have to invent prompts from nothing either. Someone has collected a set of Remotion prompts sorted into image animation, map animation, UI product demos and transparent overlays, and starting from a close one is much faster.

Exporting

Remotion renders by opening a headless browser, screenshotting every frame, and handing them to ffmpeg. This is the step that actually produces a file.

A normal mp4

One command:

1

npx remotion render TitleCards out/titlecards.mp4

Or press R in the Studio. Files default to out/. On my Ryzen 3 3200G, 1920x1080 at 30 fps for 180 frames takes about 12 seconds. The first render downloads a Chrome Headless Shell, so that one runs longer.

Transparent background (ProRes 4444)

This is the most useful export, since the cards drop straight onto a screen recording. One command does it:

1
2
3

npx remotion render TitleCardsAlpha out/overlay.mov \
  --codec=prores --prores-profile=4444 \
  --image-format=png --pixel-format=yuva444p10le

The Studio render dialog works too, but the four settings sit across three tabs and missing one gives you an opaque file:

SettingTabValue
CodecGeneralProRes
ProRes profileGeneral4444 (the default HQ has no alpha)
Image FormatPicturePNG (the default JPEG has no transparency)
Pixel formatEncodingyuva444p10le

Before any of that, make sure the composition itself has no opaque background. Set the outermost background to transparent, then check with View → Transparency as checkerboard (shortcut T). Anything transparent shows as a checkerboard:

Open the finished .mov in an ordinary player and the background is black, which looks like failure. The player just isn't drawing alpha. Drop it into an editor and it's transparent.

ProRes 4444 is large, 65.6 MB for six seconds against 750 kB for the same length in H.264. It's an intermediate format for editing, not something to distribute. For the web, VP9 in WebM (--codec=vp9 --pixel-format=yuva420p) is far smaller.

Into an editor: syncing the animation to narration

There's one last mile after the animation is done, which is lining it up with the narration. This part has nothing to do with Remotion and any editor will do. You need four features: split, speed up, slow down, freeze frame.

I use Premiere Pro. For something free, the DaVinci Resolve free tier is more than enough. Fully open-source options are Kdenlive and Shotcut.

Record the narration first, and don't change your pace to suit the animation, let the animation bend to the narration instead. You'll find the animation is short and the audio is long, so cut the animation into sections and drag each one to where the narration reaches that point. Gaps then open up between sections, and there are two ways to fill them: slow the previous section down if the gap is small, or if the gap sits on a still image, cut one frame out, freeze it, and stretch it to length.

Conclusion

Where Remotion actually saves time is on the second video. The first one costs you the work of settling the layout. After that, each video is a data change.

To pair it with an AI agent, install the official skills first. Ask an AI to write Remotion from scratch in an empty project and you generally get the old API. With the skills in place, the same prompt produces much better code. I'll put that side by side using this animation in the next post, and run GSAP, D3.js, Lottie and Three.js through Remotion while I'm at it.
