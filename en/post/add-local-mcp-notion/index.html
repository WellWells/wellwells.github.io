Add Notion MCP Locally: Three Steps for Claude Code, Codex, and Antigravity

Add Notion MCP to Claude Code, Codex, Claude Desktop, or Antigravity in three steps: one config line, OAuth in the browser, no server to host or packages to install, plus why privacy favors a local MCP.

What is MCP, and why not just use Notion's web connector?

What lets a tool like Claude or ChatGPT read and write your own Notion is the Model Context Protocol (MCP), an open standard for connecting AI tools to external services.

The easiest path is the web version: both ChatGPT and Claude on the web can connect Notion with one OAuth click. But it has a privacy downside: that connection is tied to whatever account is logged in. If you share that AI account with family, anyone using the shared account can read your Notion through the AI.

Adding MCP to a tool on your own computer instead (Claude Code, Codex, and the like) avoids that: the authorization lives only in your machine's config, so someone logging into the shared web account can't reach it, and at authorization you can tick only the pages you want to expose, leaving the rest invisible.

Don't let "MCP" or "server" scare you: you host no server and install no extra packages. We use the MCP that Notion hosts officially, authorized over OAuth: add one config line, click approve in the browser, and the tool connects itself.

Connect Notion MCP in Claude Code: OAuth in three steps

Notion's MCP offers two authentication methods, a pattern common to many MCP servers (GitHub's does the same): OAuth and a personal access token (PAT). This post leads with OAuth because it's the closest to Notion's recommended path: you connect to the server Notion hosts, with nothing to install or run locally and no extra package to maintain, and authorization is just a browser click. (For the PAT route, which gives tighter per-page control with the server on your own machine, there's a short section at the end.)

Step 1: Add it to Claude Code with one command

Adding it is one line, over the HTTP transport pointed at Notion's official MCP URL:

1

claude mcp add --transport http notion https://mcp.notion.com/mcp

It reports that it wrote to the local config:

1
2

Added HTTP MCP server notion with URL: https://mcp.notion.com/mcp to local config
File modified: /home/wells/.claude.json [project: /home/wells]

This line just records "which URL to connect to" into a local config file (~/.claude.json). It hasn't authorized anything yet. Without an explicit scope it applies to this project only, so add -s user to use it in every project.

(The URL comes in two flavors: mcp.notion.com/mcp is the newer streamable-HTTP endpoint most tools want, while mcp.notion.com/sse is for older clients that only speak SSE. --transport http with /mcp is the current standard.)

Step 2: Open Claude and run the browser authorization once

Once the config is in, launch Claude Code by running claude in your terminal. On startup it prompts you to authenticate:

1

⚠ 4 MCP servers need authentication · run /mcp

Type /mcp in a session and you'll see notion flagged as needing authentication, so select it:

   ❯ notion · △ needs authentication

Selecting it opens a browser for the OAuth flow (copy the URL manually if the browser doesn't open):

Authenticating with notion…

  ✻  A browser window will open for authentication

  If your browser doesn't open automatically, copy this URL manually (c to copy)
  https://mcp.notion.com/authorize?response_type=code&client_id=...

  If the redirect page shows a connection error, paste the URL from your browser's address bar:
  URL > http://localhost:3118/callback?code=...

If, like me, you're running Claude Code on a remote host over SSH, that last URL > line is what you need. After you approve, Notion redirects you to http://localhost:3118/callback?code=..., but that localhost is the machine your browser is on, not the remote box where Claude Code is waiting for the callback, and I hadn't forwarded port 3118 over SSH, so the page just shows a connection error. Copy that full URL from your browser's address bar and paste it into the console's URL > prompt to hand the code back to the remote. Running Claude Code locally, you won't hit this; the browser loops back on its own.

When you approve in the browser, it lets you pick which pages to expose. This is where you control what it can see. Tick only what you want to grant. It can't touch the rest.

Step 3: Confirm the connection

After authorizing, the terminal returns:

1
2

/mcp
  ⎿  Authentication successful. Connected to notion.

Seeing Connected to notion means it worked, and every time you open Claude Code from now on it reconnects automatically, and you never manually launch anything. To revoke access, disconnect notion under /mcp.

Connecting Notion MCP in Codex, Claude Desktop, and Antigravity

In one line: under the hood they all connect to Notion's hosted MCP, all authorize over OAuth, and all auto-load after setup. The only difference is whether you add it with a command, a small config block, or a click in a menu, and none of them need an extra package.

ToolHow you add itAuthorize
Claude Codeone claude mcp add command/mcp, browser opens
Codex CLI (ChatGPT)add a notion block to ~/.codex/config.tomlcodex mcp login notion, browser opens
Claude DesktopSettings → Connectors, search for notion and add it, no URL, account-boundbrowser opens on the spot
Antigravityadd a notion block to ~/.gemini/config/mcp_config.jsonreload, browser opens

Codex CLI (the terminal version of ChatGPT) does have a codex mcp add command, but it only takes local stdio servers (a launch command after --), so Notion's remote URL doesn't fit it. For a remote server the official way is to edit ~/.codex/config.toml and add this:

1
2

[mcp_servers.notion]
url = "https://mcp.notion.com/mcp"

Save, then run codex mcp login notion for the same browser authorization. (Some Codex versions treat remote MCP as experimental, so if it won't connect, add a [features] block with experimental_use_rmcp_client = true in config.toml and try again.)

Claude Desktop is even less work: no config file, no URL to paste. Go to Settings → Connectors, search for notion, click to add it, and complete the OAuth flow right there (this feature is Pro/Max/Team/Enterprise only).

A Claude Desktop connector, though, is tied to your Claude account and syncs to every device you log in on (web and mobile included), unlike Claude Code and Codex, where it lives only in a local config file. That means anyone logged into that account can read your Notion through it. So if you share your Claude account with family, don't connect it here. Use the Claude Code approach above, which stays on your machine.

Antigravity (Google's Gemini agentic IDE, which I covered in Antigravity vs. GitHub Copilot) keeps its config at ~/.gemini/config/mcp_config.json (shared by the IDE and CLI). Add a server pointed at the URL:

1
2
3
4
5
6
7

{
  "mcpServers": {
    "notion": {
      "serverUrl": "https://mcp.notion.com/mcp"
    }
  }
}

Paste it in, reload, and authorize in the browser the same way. In the UI you can find the button to open this file under Settings → Customizations.

Connect Notion with a personal access token (PAT)

If your case is headless automation, or you want the server itself running on your own machine with access scoped to a single page, Notion also offers a static personal access token (PAT): on the developer page, create a connection with Access token as the authorization type and you'll get a key starting with ntn_.... Then add the local Notion MCP server in Claude Code with that key:

1

claude mcp add notion -e NOTION_TOKEN=ntn_your_token -- npx -y @notionhq/notion-mcp-server

The @notionhq/notion-mcp-server there runs locally on your machine. Notion now actively maintains only the remote hosted MCP, and this local repo sees little upkeep, so I'd still reach for the OAuth route above first.

Conclusion

Connecting Notion to an AI tool isn't that hard: add one config line, authorize in the browser, and it connects, with no server to host and no extra packages. The tools differ only in how you add it. Underneath they all connect to Notion's official MCP. Once it's wired up, you can have Claude or Codex write Notion notes straight from the CLI, or analyze a PDF locally and drop the results right into Notion. I find it genuinely handy.

The real reason to connect this way instead of the web version's one-click is still privacy: with a tool like Claude Code that keeps the authorization in a local config, you pick the pages yourself and, even on a shared account, only you can reach it (Claude Desktop is the exception: it binds to your account, so don't use it on a shared one). So if privacy matters, I'd connect MCP locally wherever you can. And Notion isn't the only MCP worth running locally: for development there are plenty more, like Context7, Playwright MCP, Chrome DevTools MCP, and GitHub's MCP server. Wiring several of them up locally lets Claude or Codex reach more tools and pull more precise information, doing more in one pass.
