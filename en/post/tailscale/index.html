Using Tailscale to Easily Create Secure and Private Tunnels

Introduction

When you are away from home, how can you remotely connect to your home computer, work computer, or NAS at home?

This article walks you step by step through using Tailscale to reach devices on your internal network.

For Those Unfamiliar with Computers

For devices to reach each other, each one first has to be online. Tailscale then connects them.

First, register on the official website, then install and log in to Tailscale on computers A and B, mobile phones, NAS, or other devices to be networked.

After logging in, you will join the tailnet. These devices will obtain each other's internal tailnet IP address.

You can connect using device names for tasks like remote desktop connections, printing, accessing NAS, etc.

If you do not want to know about VPN backgrounds, you can skip directly to How to Install Tailscale, Renaming Devices, and Conclusion.

How to Access Devices Remotely?

Common services you might be running:

  1. Self-hosted web server (localhost:80)
  2. NAS-provided Web GUI (localhost:5000)
  3. Windows Remote Desktop Connection (localhost:3389)
  4. DNS Server (localhost:53)
  5. Other services...

If you want external users to access this server, you first need a public IP (WAN IP) address (IP Query). From outside, you connect through that public IP address.

That connection reaches your router, which you can configure to forward external ports to the corresponding applications.

The purpose is to forward public IP address:Port to internal IP address:Port.

Taking the figure above as an example, incoming connections from outside are forwarded to internal servers: DNS (192.168.1.2), web (192.168.1.3), and remote desktop (192.168.6.4, external Port 82 → internal Port 3389).

Once port forwarding is set up, you can access DNS, web, or remote desktop from outside. But the above port forwarding method allows direct access to internal network resources via public IP address, which means anyone can connect. To allow specific users to access, you must establish a virtual private network (VPN).

Creating a Virtual Private Network (VPN)

A VPN is a service that creates a secure encrypted channel to connect users to remote servers, hiding users' real IP addresses and encrypting data transmission.

For example, in Windows, based on Microsoft's official tutorial, after creating a VPN using IKEv2, L2TP, or IPsec protocol on computer A, you can try to connect from another computer B.

After a successful connection, computer B can access NAS services, printers, and other internal network resources as if it were computer A.

Make sure the router and computer aren't blocking UDP ports 500, 1701, and 4500—if they are, the VPN connection will fail.

Common VPN Protocols

  1. OpenVPN: Provides various authentication methods (key, certificate, username, and password) and can be used on different devices. It is open-source, secure, easy to use, and broadly compatible.
  2. WireGuard: Integrated into Linux in 2020, a newer VPN protocol. Its features include using UDP transmission, faster and better performance than IPsec and OpenVPN, and cross-platform support. Some newer routers integrate WireGuard servers.
  3. L2TP/IPsec: proprietary protocol (Cisco & Microsoft), built into the system. No need to install software to set up and connect.
  4. PPTP: an obsolete point-to-point protocol.

What is Tailscale?

Tailscale is VPN software based on the WireGuard protocol, connecting multiple devices into one virtual internal network.

Traditionally, setting up WireGuard is cumbersome, both in setup and maintenance. For example, on each device, you need to generate public and private keys using wg-quick, then install WireGuard, and set the relevant configuration files. The configuration files need to specify the listening port, private IP address, private key, and peer public key.

For example, a server and two clients with public and private key settings:

DevicePrivate KeyPublic KeyConfiguration
ServerABOwn private key A, client public key D and F
Client 1CDOwn private key C, server public key B
Client 2EFOwn private key E, server public key B

More clients or servers mean more complex settings, and the above example is for one server. Multiple servers would be even more complicated.

With Tailscale, you can set up a private VPN almost without generating keys or writing config files by hand, and it comes with a full Web GUI showing every connected device.

Key features of Tailscale include:

  1. Uses a mesh network instead of hub-and-spoke networks for better device communication. This is also a distinguishing feature of WireGuard compared to other VPN protocols.
  2. Supports NAT[*] hole punching, allowing two nodes behind different NATs to communicate directly without a central server, achieving peer-to-peer connections.
  3. If NAT hole punching fails, it falls back to relay mode using DERP (Designated Encrypted Relay for Packets) servers to establish connections.
  4. During Tailscale login, coordination servers are used to exchange user information such as IP address, port, and device status.
  5. Simple Web GUI management interface to manage access levels between devices.
  6. Provides features like MagicDNS[**], Taildrop, and Tailscale Funnel for easier device access.

* Network Address Translation (NAT) translates IP addresses in IP packet headers to reuse addresses, allowing all internal networks to use the same IP address to connect to external networks.

** MagicDNS lets you reach devices by name instead of remembering IPs. Taildrop works like AirDrop, sending files straight to another device. Tailscale Funnel is a reverse proxy, enabling external access to specified internal devices.

Tailscale Competitors

Similar products for creating remote networks include:

  1. ZeroTier
  2. Cloudflare Tunnel
  3. Netmaker
  4. Ngrok
  5. Twingate
  6. Others...

I have used ZeroTier, which uses its own protocol instead of WireGuard. My experience is that after devices connect to a ZeroTier private network, they get a set of internal IP addresses. Without DNS resolution, you must directly input IPs to access these devices. ZeroNSD exists, but as I recall you still have to host it yourself, so I switched to Tailscale.

How to Install Tailscale

First, register on the official website. You sign up through Google, Microsoft, GitHub, or Apple as the identity provider. Tailscale has no accounts of its own, so no passwords are stored on Tailscale.

When you log in through these accounts, you can also turn on two-factor authentication for extra security, so essentially no one can directly access your private network.

After logging in, Tailscale lists the various installation methods. Follow the official instructions to download and install. Although only Synology has an official installation package listed, other NAS can install it with Docker.

After downloading and installing, the Tailscale icon will appear in the bottom-right corner of your screen. Right-click and select Log in... to bring up the login interface. After logging in, click Connect to join the private network (tailnet).

Repeat the steps to download Tailscale on iOS or Android, log in, and click Connect. The device may ask you to add a VPN profile. Tap Add VPN and it joins the private network.

You can see newly added devices in real-time on the Web GUI.

For Linux, it is the same process but using the command line. Follow the official Linux installation tutorial. During the login process, a URL will appear, asking you to open it in a browser and log in. After a successful login, the terminal will display Success.

That completes the Tailscale install, and the devices can now reach each other. You can enter tailscale status or tailscale ping IP_ADDRESS in the command prompt to check connection status.

If it shows active; direct, the connection is direct, with ping usually 10–15 ms. Otherwise, active; relay "xxx" means it is going through a relay server, with latency around 80–300 ms.

A relayed connection usually means a firewall is blocking the UDP port, so Tailscale falls back to a relay. That is slower than a direct connection, but it still gets the devices talking.

To improve ping latency, you can check router settings or firewall for direct connection:

  1. Enable UPnP and NAT-PMP (less secure, but provides automatic configuration).
  2. Adjust firewall rules: Disable UPnP and allow internal devices to use UDP communication. Open local port 41641 (target port varies by router manufacturer). See Firewall Configuration Guide for details.
  3. On Linux, if the port is blocked, open a terminal and run: sudo ufw allow 41641/udp.

Renaming Devices

Tailnet has a built-in DNS feature that allows you to convert hostnames or device names to IP addresses (though you can still use IP addresses if you prefer 🙃).

Right-click on the icon in the bottom right corner and go to the Admin console.

By default, device names are set using hostnames. If you wish to customize the device name, you can click the ... button next to the device and rename it.

Once renamed, you can connect to devices directly using their names.

Tailscale Commands (CLI)

The Tailscale CLI allows you to enable or disable settings in a Linux environment. On Windows, there is a graphical interface, so most commands are not needed (except for some advanced features that require CLI configuration). However, it is handy for checking connection status. The table below covers the commands I use, and the official website has more detailed instructions.

CommandsDescription
tailscale statusCheck the current network status to see if it's relayed or direct
tailscale ping [IP_ADDRESS/device]Check if the device is directly connected; if "DERP" is shown, it means the connection is relayed
tailscale up [flags]Connect to tailnet with various flags
tailscale netcheckCheck the current status of DERP
tailscale updateUpdate the Tailscale version on this device

I only use a handful of these regularly. The more advanced ones can wait until I actually need them.

Here are the tailscale up settings I have used:

  • --advertise-exit-node: If computer A enables this flag, computer B can use computer A as an exit node, meaning computer B's internet traffic will appear to come from computer A's IP address.
  • --advertise-routes=<ip>: Publicize subnet routes. For example, if computer A has a local network 192.168.1.50, computer B can access the 192.168.1.xx segment directly by setting this option.

2025/5/18: I've since written a follow-up covering these settings in detail, "Advanced Tailscale Applications: Taildrop, Exit Nodes, and Subnet Routing Configuration".

Conclusion

Installing Tailscale is genuinely simple—it handles the fiddly parts like firewall and NAT traversal for you. Install it on each device, log in with the same account, and they all join the tailnet and can reach each other. Every device gets a hostname, and renaming one or checking its status both happen in the Admin console.

A device already in the tailnet can also act as a subnet router, advertising its whole segment to the rest of the tailnet, and you can share an individual node (Sharing nodes) with another account to build more complex setups. The official website covers all of this in more depth.
